The correct services to use are AWS CloudWatch Events (now called EventBridge) and AWS Simple Notification Service (SNS).

Here's why:

  • AWS CloudWatch Events can be set up to detect specific state changes in CodePipeline, such as a pipeline or a stage moving into the FAILED state. You can create a rule to trigger whenever this happens.
  • AWS SNS is a managed notification service that enables you to send notifications via multiple protocols, including email and SMS. By connecting SNS to CloudWatch Events, you can immediately alert your team members using both channels.

Why the other options are less suitable:

  • AWS Simple Queue Service (SQS) is primarily intended for decoupling microservices or for message buffering; it doesn't directly handle notification delivery via email/SMS for alerting users upon pipeline failures.
  • AWS CloudWatch Alarms are focused on metrics-based alarms. CodePipeline state changes (like FAILED) are typically reported as events, not metrics, making alarms inappropriate for this use case.
  • AWS CloudTrail tracks API calls and account activity for auditing but does not offer native notification delivery mechanisms or direct event pattern matching needed for instant alerts.

Tips: Set up a CloudWatch Event rule filtering for 'FAILED' state changes in your pipelines, and configure the target as an SNS topic. Subscribe your on-call team's email and phone numbers to that topic to ensure real-time, multi-channel notifications.
