Within the CloudWatch Log Group, configure a subscription filter that directs log events to the Lambda function, specifying the required filter pattern. This is the correct approach because CloudWatch Log Groups support subscription filters, which let you stream selected log events to AWS Lambda or other services based on real-time pattern matching. The subscription filter uses a filter pattern so only the events that include your desired keywords are delivered to Lambda immediately for processing.

The other options are incorrect for these reasons:

  • Choose the CloudWatch Log Group and use the 'Export data to Lambda' feature, selecting your Lambda and setting the appropriate filter pattern. — There's no built-in feature in CloudWatch to directly 'Export data to Lambda'; this workflow does not exist.
  • From the CloudWatch Log Group, pick the log stream and select 'Export results', assign your Lambda function, and provide the filter pattern. — Exporting log stream results is primarily for static exports (like to S3), not real-time processing by Lambda.
  • Set up a metric filter in the CloudWatch Log Group to send filtered log data to the Lambda function and define the search pattern within this metric filter. — Metric filters are for generating CloudWatch Metrics from log events, not for streaming filtered event data directly to Lambda in real-time.

Tips and Insights:
When automating real-time log event processing with Lambda, always use subscription filters, which provide both filtering and streaming capabilities. The filter pattern should be crafted carefully to avoid unintentional invocation of your Lambda function, keeping costs and unwanted triggers minimal.
