The correct answers are: Aurora Global Database provides support for both the Aurora MySQL and Aurora PostgreSQL engines, You can promote the secondary cluster to a standalone, fully writable instance for disaster recovery scenarios, and The secondary cluster placed in us-east-1 helps deliver low-latency reads to users in that region.

  • Aurora Global Database provides support for both the Aurora MySQL and Aurora PostgreSQL engines: Aurora Global Database is capable of supporting both popular Aurora database engines, which offers flexibility in database technology choice when deploying globally distributed workloads.
  • You can promote the secondary cluster to a standalone, fully writable instance for disaster recovery scenarios: In case the primary region becomes unavailable, Aurora allows you to promote a secondary cluster into a standalone cluster, enabling full read/write operations so you can quickly restore availability for your applications in a new region.
  • The secondary cluster placed in us-east-1 helps deliver low-latency reads to users in that region: Aurora Global Database replicates changes with latencies typically less than 1 second, so applications in the us-east-1 region can read from the geographically closer secondary, reducing read latency for North American users.
  • There are no charges incurred for replicating write operations from the primary to the secondary region: This is incorrect. Aurora charges for replicated write I/O between regions. The replication traffic, including network data transfer and write operations, incurs charges.
  • Both the primary and secondary clusters have identical configurations for read and write capacity: This is not accurate. Only the primary cluster supports write operations. Secondary clusters are read-only until you promote them. Their instance counts and capacities may also differ from the primary cluster, based on your HA and scaling needs.

Tip: Use Aurora Global Database to achieve low-latency global reads and cross-region disaster recovery, but remember that only the primary cluster is writable under normal conditions and additional costs apply for multi-region replication.
