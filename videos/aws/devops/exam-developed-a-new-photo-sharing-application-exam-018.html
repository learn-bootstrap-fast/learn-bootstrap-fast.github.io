The correct approach is to update the launch configuration to use C3 in your CloudFormation template and add an UpdatePolicy for AutoScalingRollingUpdate, then run a stack update. The UpdatePolicy ensures rolling updates, which means old instances are gradually replaced with new ones running the C3 instance type, minimizing downtime for users.

Why other options are incorrect:

  • Make changes to the AWS Management Console, creating a new launch configuration for C3 instances, then update the Auto Scaling group with this configuration. Existing instances will automatically switch instance types. – This is incorrect because existing instances do not change their type automatically (live in-place modification is not possible); they are only replaced as part of scaling actions or rolling updates.
  • Directly update the existing launch configuration through the AWS Management Console to use C3 instances, and add an UpdatePolicy of AutoScalingRollingUpdate to your Auto Scaling group. – This option suggests editing an existing launch configuration, but launch configurations are immutable; you must create a new one. Also, changes through the console don’t link to CloudFormation management and can cause drift from the stack.
  • Change the launch configuration to use C3 in your CloudFormation template, then update the stack with this template. Automatic replacement of the instances with new types will follow. – While this updates the launch configuration, it does not specify an UpdatePolicy, so CloudFormation terminates and replaces all instances at once, causing disruption.

Tip: Always include an AutoScalingRollingUpdate UpdatePolicy for controlled Auto Scaling group updates using CloudFormation to ensure minimal service impact and smooth instance type transitions.
