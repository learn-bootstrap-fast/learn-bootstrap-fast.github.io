The best solution is to use AWS Lambda, as it can be natively triggered by DynamoDB Streams whenever there’s a new entry or modification in the table. Your Lambda function can process the stream payload (the new photo information) and send notifications to users’ friends, possibly by publishing a message to an SNS topic or through other messaging integrations.

Set up an S3 bucket to process DynamoDB Stream events and notify users is incorrect because S3 buckets can’t directly receive or process DynamoDB Stream records. Create a CloudWatch Events rule to trigger actions from the stream is not viable since CloudWatch Events does not integrate directly with DynamoDB Streams. Utilize SNS to directly process notifications from DynamoDB Streams is wrong because SNS cannot consume DynamoDB Stream events directly; you need an intermediate processor (such as Lambda) in between.

Tip: When you want to react to data changes in DynamoDB tables, Lambda offers a serverless and seamless way to process change events and implement business logic immediately.
