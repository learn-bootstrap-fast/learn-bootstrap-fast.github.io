The best solution is to use a CloudWatch alarm set to trigger an EC2 recovery action when the StatusCheckFailed_System metric is detected. This leverages native AWS automation, allowing CloudWatch to monitor the health of your EC2 instances and automatically attempt to recover an instance that fails its system status check, all without manual oversight. This method is highly reliable, requires minimal configuration, and fully integrates with AWS.

The following options are not optimal: Develop a script to query each EC2 instance's status check through the EC2 API at set intervals requires manual scripting, extra maintenance, and handling of edge cases; it's more complicated than the native option. Create a recurring script to shut down and reboot EC2 instances based on health statistics risks unnecessary instabilities, and doesn't directly target system status check failures. Employ a third-party monitoring application for all your EC2 instance health checks introduces more cost, more complexity, and is not required for this use-case since AWS gives you built-in tools for automation.

Tip: When you see a question about automatically fixing instance/system status check failures in EC2, remember that CloudWatch alarms with EC2 recover actions are purpose-built for this scenario.
