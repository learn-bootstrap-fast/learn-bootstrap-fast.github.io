You can stream CloudWatch Logs to destination services that support real-time ingestion and processing for advanced analysis.

The correct answers are AWS Lambda function and AWS Elasticsearch (now known as Amazon OpenSearch Service). These can be directly configured as CloudWatch Logs subscription destinations:

  • AWS Lambda function can be triggered in real time by incoming log events, enabling you to run custom code for alerting, filtering, transformation, or sending data elsewhere.
  • AWS Elasticsearch allows direct streaming of logs for search, analysis, and visualization, powering dashboards and operational insight tools.

Why other options are incorrect:
  • AWS S3 is not a native subscription destination for CloudWatch Logs—logs can't be streamed directly. Instead, you must use a Lambda, Firehose, or another intermediary to deliver logs to S3.
  • AWS CloudTrail is a service that generates audit logs, but is not a target or destination for CloudWatch Logs streaming.
  • AWS DynamoDB is a NoSQL database and not an endpoint for CloudWatch Logs subscriptions—logs cannot be streamed directly from CloudWatch Logs to DynamoDB.

Insight: When needing real-time log processing or indexing, always consider Lambda and Elasticsearch as possible stream destinations for CloudWatch Logs.
Tip: Remember that sending logs to S3 usually involves an intermediate step like Kinesis Data Firehose or Lambda, while Elasticsearch and Lambda can receive logs directly from CloudWatch Logs subscriptions.
