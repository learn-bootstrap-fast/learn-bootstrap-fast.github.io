The best approach is to use AWS Lambda in combination with AWS Step Functions. AWS Step Functions natively supports the creation of visual, workflow-driven state machines. Each state in a Step Functions workflow can directly invoke a Lambda function, which aligns perfectly with the requirement that each deployment stage should execute as a separate Lambda. Additionally, Step Functions integrates seamlessly with CloudFormation and provides visual monitoring and error handling, making it ideal for managing complex deployment logic such as stack creation or change set review.

The other options are less suitable:

  • Implement a Python script on an EC2 instance to track state... - While technically possible, this adds unnecessary complexity, manual state tracking, and additional resource management overhead, lacking the native visualization and orchestration features of Step Functions.
  • Create multiple SQS queues to indicate stack deployment status... - SQS is built for message queuing, not for orchestrating or visualizing workflows as a state machine. Implementing state transitions through SQS would be error-prone and hard to manage visually.
  • Deploy a shell script on an EC2 server that uses AWS MQ... - This approach introduces even more operational burden by depending on EC2 and MQ. AWS MQ is intended for message brokering, not state machine orchestration, and offers no built-in support for workflow visualization.

Tip: AWS Step Functions offers serverless state management, visual monitoring, and robust error handling, making it the preferred solution for orchestrating and visualizing multi-step workflows in AWS deployments.
