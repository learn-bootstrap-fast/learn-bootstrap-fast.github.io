The correct approach is to set the Action Mode to “Create or replace a change set” in the CloudFormation deployment action of your CodePipeline. This configuration causes CloudFormation to generate a change set—a summary of intended modifications to the resources in your stack—without immediately executing them. You can then add an approval or manual deploy stage where team members can review and approve the changes. If accepted, a subsequent pipeline action can execute the change set, safely applying the updates.

Choosing “Alter the Action Mode to ‘Delete a stack’...” is not practical, as this would destroy your current resources and may result in loss of data or downtime. The option to “Switch the deployment provider from CloudFormation to CodeDeploy...” does not solve the problem, since CodeDeploy is not intended for managing CloudFormation stacks directly, and the underlying issue of stack updates remains. Finally, only improving the “Update the code review procedures...” reduces but does not eliminate the risk of human error—it does not allow in-place preview and approval of resource changes within the pipeline.

Tip: Using change sets in CloudFormation is a best practice for previewing and vetting potentially disruptive stack changes in automated deployments, reducing unintentional outages or configuration drift.
