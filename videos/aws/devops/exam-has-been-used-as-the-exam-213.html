It is possible for a user to pick a custom S3 bucket as the artifact storage location during pipeline creation and A user is allowed to set up a default S3 bucket in the same AWS region and account as the pipeline to serve as the artifact store are correct.

Explanation and Tips:
Amazon S3 is the primary, and in practice the only, storage backend for artifacts in AWS CodePipeline. Using Amazon S3 ensures artifacts are securely managed with high durability and availability, aligning with most security policies for regulated industries.

  • Custom S3 buckets can be created or selected for each pipeline, giving you flexibility and allowing you to align with security best practices (e.g., KMS encryption, versioning, and bucket policies).
  • A default S3 bucket can automatically be created by CodePipeline in the same AWS region and account to store your pipeline artifacts if you opt not to specify a custom bucket. Artifacts must reside in a bucket in the same region and account as the pipeline.

Why Other Answers Are Incorrect:

  • Pipeline artifacts can be stored on either Amazon S3 or Amazon EC2 EBS volumes. — This is incorrect because only Amazon S3 is supported for artifact storage; EBS is not used or supported for this purpose.
  • When storing artifacts in S3, the bucket may be situated in another AWS region. — This is not allowed. CodePipeline requires that the artifact bucket be in the same region as the pipeline for security and latency reasons.
  • If CodeBuild is utilized for building, the user cannot specify output artifacts, only input artifacts. — This is incorrect. With CodeBuild actions, you can define both input and output artifacts, enabling you to pass files or build results between stages.

Exam tip: When dealing with artifact storage, always link it back to S3, not EBS or other services. Remember S3's durability, regional restrictions, and the ability to specify custom or default buckets.
