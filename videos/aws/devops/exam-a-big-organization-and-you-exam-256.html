The correct mechanism to get notified when a security group allows unrestricted SSH is to use the Set up an AWS Config rule by choosing the AWS Managed rule named \"restricted-ssh,\" which evaluates whether security groups allow SSH access from all locations option. The AWS Config managed rule \"restricted-ssh\" specifically checks if security groups are permitting inbound SSH from the entire internet (0.0.0.0/0); when non-compliance is detected, Config can trigger notifications via SNS, Lambda, or other integrations for real-time alerts.

The option \"Create a rule in AWS Config and utilize the Managed rule 'restricted-common-ports' to automatically assess if any security group permits open SSH ingress\" is incorrect because the \"restricted-common-ports\" rule checks a range of common ports, but for precise SSH access notification, \"restricted-ssh\" is specifically designed for port 22.

\"Activate Amazon Inspector and add the rule set 'Common Vulnerabilities and Exposures-1.1' to inspect security groups and set up alerting via SNS\" is not suitable, because while Inspector mainly scans for vulnerabilities on EC2 instances themselves, it does not continuously evaluate security group configurations for future changes or for specific SSH access risk.

The option \"Turn on Amazon GuardDuty and review findings regarding open security groups using AWS Security Hub\" is incorrect since GuardDuty primarily monitors for suspicious activity, but does not provide real-time compliance checks or notifications when security groups are made publicly accessible for SSH. Security Hub aggregates findings, but it is not intended for direct security group change notification.

Tip: AWS Config rules are the purpose-built solution for monitoring compliance of resource configurations, including security groups. To ensure immediate notification, pair AWS Config rule evaluations with SNS topics to trigger alerts when non-compliance, such as unrestricted SSH, is detected.
