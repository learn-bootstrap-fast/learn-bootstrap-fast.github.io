The correct way to move an instance from the 'Wait' state to 'InService' after your custom initialization is complete (such as after a user data script successfully passes a health check) is to have your script call the complete-lifecycle-action command. This tells the Auto Scaling lifecycle hook that your custom actions have finished and the lifecycle hook can conclude. This returns the instance to normal ASG operation and marks it as 'InService'.

Why the other options are incorrect:

  • Invoke the CLI command put-lifecycle-hook within the script... – The put-lifecycle-hook command is for creating or updating lifecycle hooks, not for completing a lifecycle action for a specific instance. It does not move an instance out of the Wait state.
  • Make use of attach-instances from the AWS CLI... – The attach-instances command is meant for manually adding existing EC2 instances to an Auto Scaling group. It does not affect lifecycle hooks or the specific ASG lifecycle state transitions resulting from hooks.
  • Configure your script to run record-lifecycle-action-heartbeat... – The command record-lifecycle-action-heartbeat is used to keep an instance in the Wait state longer by heartbeating, but does not end the wait or complete the lifecycle action. You still need to call complete-lifecycle-action to finish the hook and bring the instance into service.

Tip: Always use 'complete-lifecycle-action' at the end of your initialization logic to ensure Auto Scaling recognizes that your instance is ready for traffic.
