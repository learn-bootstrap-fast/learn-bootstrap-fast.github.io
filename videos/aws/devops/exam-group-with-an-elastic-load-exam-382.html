To phase out all running instances in an Auto Scaling group and replace them with a different instance type, there are two main approaches:

  • Apply the OldestLaunchConfiguration policy: This method ensures that instances created with the outdated setup are replaced first, promoting a smooth transition to the new configuration and removing all instances derived from the earlier launch configuration.
  • Introduce another Auto Scaling group under the existing ELB: By adding a fresh Auto Scaling group with the new instance type and attaching it to the same Elastic Load Balancer, you can gradually increase the desired capacity of the new group while reducing it in the old group, seamlessly migrating all serving capacity to the updated instances.

Apply the NewestInstance strategy is incorrect because this approach targets the most recently created instances, not necessarily those using the previous configuration, which could leave older instances unchanged.
Connect an extra Elastic Load Balancer to the Auto Scaling group... is not a recognized method for phasing out specific instance types or effectively managing instance replacement.

Tip: Use rolling upgrades or multiple Auto Scaling groups with careful ELB management for safe, zero-downtime instance transitions.
