Amazon ElastiCache and Amazon RDS Read Replicas are the best choices for scaling the data tier and reducing query load for a read-intensive application:

  • Add Amazon ElastiCache: Caching common queries in ElastiCache (either Redis or Memcached) means subsequent requests can be served from in-memory storage, greatly reducing the number of queries that hit the RDS database and improving response times. This is particularly effective for data that doesn't change frequently or is requested often.
  • Introduce an Amazon RDS Read Replica: Read replicas let you offload read-heavy workloads from the primary DB instance to one or more replicas, which can be used to service read-only queries, thereby alleviating bottlenecks on the main RDS instance.

Why the other options are less suitable:

  • Set up Auto Scaling for your database tier to automatically add and remove database servers based on demand. – Traditional Auto Scaling is not natively supported for RDS databases since RDS instances do not scale horizontally in the same way EC2 instances do. Scaling up an RDS instance usually requires changing the instance type or adding read replicas, not Auto Scaling groups.
  • Utilize SQS to store query results for quick access. – Amazon SQS is designed for reliable message queuing between components of distributed systems. It's not a caching mechanism and isn't designed for storing or retrieving query results, so it would not help reduce direct database read loads.

Tip: For read-intensive applications, effective caching and the use of read replicas are AWS best practices to drastically improve performance and scalability at the database layer.
