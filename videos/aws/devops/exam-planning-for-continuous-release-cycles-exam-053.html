The correct answers are Use AWS Elastic Beanstalk and leverage 'Application Versions' and Deploy your web application using AWS OpsWorks. Both services offer robust application deployment with built-in capabilities for rolling back to former versions:

  • Elastic Beanstalk Application Versions: You can upload multiple versions of your application and select any version to deploy at any time, which streamlines rolling back when a release causes issues. Beanstalk automatically manages environment orchestration and rollback, making it particularly suitable for CI/CD pipelines that need version control and minimal downtime.
  • OpsWorks: This service is based on Chef or Puppet, allowing versioned deployments of your application in layers. You can quickly redeploy a previous version of the app using the Deploy functionality, enabling fast recovery from release errors.
  • Set up distinct Elastic Beanstalk environments...: While using multiple environments is a valid deployment pattern for blue/green deployments or parallel testing, it is not an efficient method for version-level rollbacks, as it involves duplicating resources and complicating environment management.
  • Use AWS CloudFormation by creating separate templates...: CloudFormation is intended for infrastructure provisioning and versioning your infrastructure, not for managing application code releases. Creating separate stacks for each code revision leads to unwieldy management and is not recommended for deploying and rolling back application releases.

Tip: Always use platform features like Beanstalk Application Versions or OpsWorks deployment automation for application management. Relying on infrastructure-as-code or multiple environments for versioning your actual application code is less scalable and introduces unnecessary complexity.
