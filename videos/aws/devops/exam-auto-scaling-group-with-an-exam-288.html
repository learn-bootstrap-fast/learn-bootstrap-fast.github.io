The correct answers are: Put the problematic instance into Standby mode and Attach a lifecycle hook that places the instance in Pending:Wait status for up to 24 hours.

  • Standby Mode: By putting the instance in Standby, it is temporarily detached from the Auto Scaling group, meaning it won't be terminated due to failing health checks. This allows you to connect and troubleshoot the instance without interference from Auto Scaling processes.
  • Lifecycle Hook – Pending:Wait: When using a lifecycle hook at the time of instance launch, the instance is paused in the Pending:Wait state, preventing it from proceeding to become 'InService'. The timeout can be extended up to 48 hours, so you have at least 24 hours to investigate.

Why the other options fail:

  • Edit the ASG’s health checks to disable Elastic Load Balancing (ELB) health monitoring: Simply disabling ELB health checks could cause the ASG to rely on EC2 health checks, but unhealthy instances may still be terminated, or you might miss crucial load balancer-specific issues.
  • Revert the AMI ID in the launch template to the previous version: This would not keep the new instance running for troubleshooting. Any failed health check would still cause instance termination by the ASG mechanism.
  • Decrease the desired instance count in the Auto Scaling group to reduce terminations: Lowering the desired count only reduces the number of running instances, but doesn’t guarantee that any single instance will stay up for troubleshooting, nor does it isolate an instance from health checks and terminations.

Tip: Use Standby mode to isolate and retain specific instances. Lifecycle hooks are valuable for pausing an instance’s lifecycle at key stages. Both approaches offer safe avenues for in-depth troubleshooting without prematurely losing instances to automated recovery actions.
