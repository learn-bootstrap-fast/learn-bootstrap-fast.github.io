The Update your configuration management tool with new instructions that will routinely generate and rotate the application's AWS access keys, then prepare and deliver a compliance report to your VP option is the most complete and effective solution for maintaining key rotation best practices and providing the compliance reporting your VP requires. Regularly rotating access keys limits the potential impact of leaked credentials and ensures compliance with security standards such as not having access keys older than six months.

The option Build a script that queries the IAM ListAccessKeys API so you can gather the application's access key creation dates and routinely generate a compliance report for your VP will give you information about access key age, but it does nothing to enforce actual rotation; it only surfaces compliance issues without resolving them.

Choosing Send the VP the documentation link from AWS IAM to address access key rotation concerns is ineffective, since simply providing documentation does not address real-world compliance or reporting requirements.

Finally, Modify the application to log all changes to its AWS credential files and analyze them with Amazon EMR jobs to periodically generate compliance reports is overly complex, introduces unnecessary components, and does not guarantee adherence to best practices for key rotation.

  • Tip: Always implement automated key rotation mechanisms in conjunction with regular compliance reporting for security-sensitive AWS applications.
