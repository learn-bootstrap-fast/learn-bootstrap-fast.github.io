The most effective way to scale a web application in this situation is to use an Auto Scaling group to spin up several EC2 instances and route traffic through an Elastic Load Balancer. This approach allows your application to automatically increase or decrease the number of running instances based on demand, distributing user requests for consistent performance. The Elastic Load Balancer helps evenly direct traffic, greatly improving scalability and reliability.

The option Utilize Auto Scaling launch configurations to deploy multiple EC2 instances and locate them behind a load balancer is similar, but launch configurations have been replaced with launch templates for new AWS environments, and launch configurations alone do not provide end-to-end scaling management without being tied to an Auto Scaling group.

Choosing Implement CloudFormation to redeploy the application with an Amazon RDS Multi-AZ setup and Choose Amazon RDS using the Multi-AZ option focuses only on the database layer’s high availability and fault tolerance. These would not solve slow response times stemming from a single overloaded EC2 instance serving the web application, so they do not directly address application scalability or web layer load distribution.

  • Tip: For most web applications, horizontal scaling (adding more compute resources and balancing them behind a load balancer) is the best way to support growing user demand.
