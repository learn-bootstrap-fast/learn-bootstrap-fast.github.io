The correct strategy is to address resource drift or stack failure by first reconciling underlying resource states with CloudFormation’s expectations—potentially by making manual changes outside CloudFormation. Afterwards, you should invoke ContinueUpdateRollback with the ResourcesToSkip parameter, which allows CloudFormation to mark the skipped resources as UPDATE_COMPLETE and continue the rollback operation. If, during stack deletion, a DELETE_FAILED status is encountered, making use of DeleteStack along with the RetainResources parameter enables you to remove the stack while retaining non-removable resources.
