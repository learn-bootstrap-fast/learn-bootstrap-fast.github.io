The correct approach is to set up a single CloudWatch dashboard that collects and presents metrics from multiple AWS regions. This enables you to have a consolidated view of your EC2 fleet's health and activity across geographic boundaries, without managing separate dashboards for each region. CloudWatch supports cross-region metrics on a dashboard as long as you specify the region for each widget.

Option 'Register EC2 servers operating in different regions directly with CloudWatch to monitor them.' is misleading: EC2 instances automatically send metrics to CloudWatch in their own region; there is no manual 'registration' needed for standard metrics.

Option 'It is not possible to gather EC2 performance details from multiple regions using CloudWatch.' is incorrect. Cross-region monitoring is a supported feature using CloudWatch dashboards.

Option 'You have to create unique dashboards for each AWS region to view their respective metrics.' is outdated. AWS CloudWatch dashboards allow you to pull metrics from any region into one dashboard, making it easy to visualize global workloads.

Tip: When adding widgets to a CloudWatch dashboard, specify the desired region for each widget to monitor resources globally from a single pane of glass.
