The most direct method is to use View AWS CloudTrail's Event History and search for 'DeleteParameter' and 'DeleteParameters' activities filtered to the last week. Review the event details for relevant entries. CloudTrail records all API activity, including deletions in AWS Systems Manager Parameter Store. By searching for these specific delete operations, you can find out exactly who performed the action, when it happened, and the details of the deleted parameter.

Let’s address why the other options aren’t suitable:
Set up a new AWS Config rule to monitor for parameter deletion operations and configure it to report to an SNS topic. – AWS Config does not directly track delete events for Parameter Store values. Config rules are generally used for configuration drift and compliance, not real-time event auditing.
Establish a CloudWatch Events rule for 'DeleteParameter' and 'DeleteParameters', triggering email notifications with the included event data. – While this approach can notify administrators of future deletions, it will not surface information about deletions that have already taken place before the rule was configured.
Locate the parameter under AWS Config resources and examine the Compliance Timeline to determine when the parameter became non-compliant. – AWS Config may not record Parameter Store deletions in a directly actionable or timely way, and there may not be a compliance timeline tied specifically to parameter deletions.

Tip: For forensic or retrospective investigations of API activities, CloudTrail is your primary resource. You can filter by event type and quickly identify who did what and when.
