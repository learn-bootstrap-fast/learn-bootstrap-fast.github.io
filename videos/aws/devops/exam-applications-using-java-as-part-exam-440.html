The statement There must only ever be one buildspec file associated with a single build project. is incorrect. AWS CodeBuild lets you utilize different buildspec files as needed for various scenarios, such as testing, staging, or production environments. You can specify a custom buildspec filename either directly within the build project settings or at build time. This feature makes it possible to manage multiple build specs for a single project.

Option You are allowed to change the name of the build spec file to something like buildspec_test.yml, on a per-build basis. is correct, as CodeBuild enables you to define a custom buildspec file name when starting the build or in project settings, offering flexibility for different builds.

Option It's possible to keep your buildspec file together with your application's source code in the same location. is also correct, since the buildspec file is often stored alongside the application code in your repository, facilitating version control and easy access.

Option Buildspec files must always use JSON syntax to be valid in CodeBuild. is incorrect as well. While you can use either YAML or JSON, YAML is the default and more commonly used format for buildspec files in CodeBuild.

Tip: Consider leveraging multiple buildspec files to support various environments or test scenarios. Also, aim for storing your buildspec file in the repository root and use YAML for clarity and readability.
