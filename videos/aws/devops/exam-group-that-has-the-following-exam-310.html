The correct choice is Modify the Minimum capacity to 2. The minimum capacity in an Auto Scaling group defines the fewest number of instances that must be running at all times. By setting this value to 2, the group will never have less than 2 instances, even if demand drops or scaling policies are triggered.

The other options do not guarantee that two instances are always running:

  • Adjust the Desired capacity to 4: This sets the target number of instances to 4, which might temporarily increase the number of running instances, but if scaling policies decrease the desired or minimum capacity, the count can still fall below 2 eventually.
  • Suspend the Launch process within the Auto Scaling Group: Doing this halts the ability to launch new instances, which can prevent the group from maintaining even the current instance count if one terminates.
  • Lower the Maximum capacity to 2: This action only restricts the upper limit. If the minimum or desired capacity is less than 2, there is still no guarantee that 2 instances will always run.

Tip: The minimum capacity makes sure the group will never go below a specific number of instances, fulfilling the requirement directly.
