The right action is to select Change the Deployment preferences to ignore health check results during deployment. Elastic Beanstalk allows you to override normal behavior by specifying that health check failures should not block deployments. By enabling the 'Ignore health check' option, the deployment can complete successfully, even when the health checks are failing, which is suitable if failures are expected during rollout (as is the case here).

The other options are not correct for the following reasons:

  • Increase the command timeout value for Health Checks in Deployment settings, for instance from 600 seconds to 1200 seconds. – This only delays the failure, it doesn't ensure success when failure is expected and persistent, as in this scenario.
  • Lower the pass criteria for the health check from OK to Degraded to allow the deployment through. – This would make the system less reliable, as it would allow degraded instances to pass health checks, but doesn't guarantee the deployment will succeed if the root cause still leads to failed checks.
  • Switch the deployment method from Rolling to All at Once. – Changing the deployment type does not address the underlying issue of health check failures; even in an all-at-once deployment, failed health checks can cause rollback.

Tip: Use the 'Ignore health check' option only when you are certain the health check issue is understood and not unexpected, as ignoring legitimate health failures can allow faulty code into production.
