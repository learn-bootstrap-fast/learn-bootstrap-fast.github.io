The best answer is Implement AWS CodePipeline with ECR as the source and ECS as the deployment target, leveraging a CodeDeploy application and deployment group to manage blue/green updates. This approach natively integrates with AWS-managed CI/CD services and utilizes CodeDeploy's native blue/green deployment capabilities for ECS, greatly simplifying management and automation. CodePipeline natively supports ECR image triggers as sources and can orchestrate deployments through CodeDeploy without the need for custom scripting or self-managed infrastructure.

Set up a Jenkins server on an EC2 instance, configure a Jenkins job with a source stage that pulls the image from ECR and a deployment stage to ECS by running AWS CLI commands is incorrect because hosting Jenkins adds operational overhead, requires manual integration effort, and does not utilize the managed blue/green features that CodeDeploy offers for ECS.

Use AWS CodePipeline with ECR configured as the source stage, CodeBuild to build the docker image, and CloudFormation to automate the ECS cluster deployment is not the quickest solution, as the Docker images already reside in ECR so a build stage with CodeBuild is unnecessary. Furthermore, CloudFormation is typically for infrastructure setup rather than orchestrating blue/green app deployments.

Create a CodeDeploy application and assign a deployment group to enable blue/green deployment from ECR directly to the ECS cluster misses the orchestration provided by a pipeline service—CodeDeploy does not offer a full end-to-end pipeline experience and lacks integration steps such as source artifact tracking that are available in CodePipeline.

Tip: To deploy containers on ECS using blue/green deployment, use CodePipeline with ECR and CodeDeploy integration. This lets you orchestrate the entire flow with native AWS services, reduces manual setup, and supports automation. Always avoid unnecessary custom tooling when managed options are available.
