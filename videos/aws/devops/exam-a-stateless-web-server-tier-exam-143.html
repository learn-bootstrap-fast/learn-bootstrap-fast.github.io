Correct Answers:
- Launch an Auto Scaling group for the web tier and define a scaling policy that leverages the EC2 instance CPU usage CloudWatch metric for scaling decisions.
- For the database tier, implement an Auto Scaling group and use the Amazon RDS read replica lag CloudWatch metric to automatically scale out read replicas.

Explanation:

  • The use of EC2 Auto Scaling (second option) makes the web server layer self-healing by automatically launching new instances if the current ones fail or are terminated. By tracking EC2's CPU utilization with CloudWatch, you can maintain enough capacity to handle varying load and replace unhealthy instances, making fault recovery automated.
  • Auto Scaling the read replicas in the database layer (fourth option) based on RDS read replica lag ensures that additional replicas are spun up as needed to handle increased read requests or failures, allowing the system to recover seamlessly if a read replica becomes unhealthy or lags behind.

Incorrect Options:

  • Create an Auto Scaling group for the web server tier and configure scaling based on Amazon RDS DB CPU utilization metrics provided by CloudWatch: This is incorrect because scaling the web tier should not be tied to the database's CPU utilization; scaling decisions for web servers should reflect their own workload metrics.
  • Resize both the EC2 instances for web servers and RDS database instances to larger instance types to prevent them from turning unhealthy: Simply using bigger instances doesn't make the system self-healing. It only increases resource allocation and doesn't address automatic recovery or failover.
  • Configure the database with an Amazon RDS Multi-AZ setup: While Multi-AZ allows automated failover for increased availability, it does not provide self-healing with regards to read scaling or replacing failed web/application servers. Multi-AZ applies to high availability of the primary database instance.

Tip: For architecting self-healing systems, focus on automated replacement/recovery (e.g., Auto Scaling groups, health checks, read replica scaling) rather than simply adding resources or availability features without automation.
