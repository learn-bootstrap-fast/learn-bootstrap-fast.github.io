The correct approach is to allow the IAM role attached to the EC2 instance to provide temporary credentials via AWS STS, which are automatically used by AWS SDKs. This means that, when you use IAM roles with your EC2 instance, the SDK on the instance will directly interact with the instance metadata service to retrieve temporary API credentials behind the scenes. Application code does not need to manually fetch or manage these credentials; the entire process is handled securely by AWS infrastructure.

Here's why the other choices are not suitable:

  • You should modify your application's code to send a GET request to the IAM Service API, which will provide the required credentials for the user. — This is not the recommended way. Credentials are not fetched directly from IAM via GET requests; instead, roles and the metadata service manage this for you.
  • Select your used SDK in the EC2 console's “Chosen SDK” list, enabling the instance to install the right SDK on startup and configure API keys accordingly. — There is no such option for selecting an SDK in the EC2 console that auto-configures the correct credentials. You must attach a role to the instance instead.
  • Configure your application code to instruct the AWS SDK to use environment variables for API keys, as assigning a role to an EC2 instance will automatically set these variables at launch. — While SDKs can read credentials from environment variables, IAM roles do not automatically establish these variables. Instead, SDKs interact with the instance metadata service to retrieve credentials associated with the instance profile.

Tip: Assigning an IAM role to your EC2 instance is the most secure way to manage credentials for your application, eliminating the need to hardcode or manually fetch API keys.
