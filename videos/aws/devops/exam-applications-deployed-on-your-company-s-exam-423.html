All EC2 instances are required to have the SSM Agent installed and you must assign an IAM role to the EC2 instances that allows SSM Run Command actions. These steps are necessary so that AWS Inspector can communicate with the instances and perform vulnerability assessments. AWS Inspector utilizes AWS Systems Manager (SSM) for agentless scanning, which requires both the SSM Agent and the correct IAM permissions for operations like Run Command.

Option The EC2 instances should permit inbound SSH traffic (port 22) in their security groups is incorrect because Inspector and SSM do not require SSH access; SSM uses secure internal channels across AWS networks.

Option Ensure AWS CLI is installed on all of the EC2 instances prior to assessment is unnecessary for AWS Inspector scanning, as the CLI is not required by Inspector.

Option Configure the EC2 instance IAM role to grant full AWS Inspector permissions is incorrect—Inspector permissions should be managed at the Inspector service level, not assigned directly to EC2 instance roles. Instead, the EC2 role must have permissions related to SSM.

Tip: Always ensure your EC2 instances meet AWS Inspector prerequisites: SSM agent (for agentless scanning), required IAM roles (allowing SSM actions), and a secure VPC configuration that does not mandate exposing management ports like SSH to the internet.
