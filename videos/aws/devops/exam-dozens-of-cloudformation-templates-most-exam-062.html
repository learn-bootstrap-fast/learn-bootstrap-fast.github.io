The best ways to automate AMI selection for CloudFormation are Including an AMI ID parameter in the templates and using a custom resource that invokes a Lambda to retrieve the latest AMI. The first option minimizes template edits—users simply enter or script the newest AMI ID when launching or updating stacks. The custom resource approach fully automates this, enabling CloudFormation to dynamically fetch and use the most current AMI at stack runtime via Lambda. This is more resilient and scalable for large environments.

Option \"Utilize a CloudWatch Event rule...\" is incorrect because simply running a Lambda function daily doesn't update CloudFormation stacks automatically. Option \"Write a script that uses the AWS CLI...\" requires manual or external process integration and doesn't directly tie into CloudFormation's automation capabilities. Option \"Create a Lambda function capable of querying AWS...\" only addresses part of the problem—the Lambda function must be integrated as a custom resource within the CloudFormation template for truly automated and context-aware stack builds.

  • Tip: Using custom resources with Lambda offers a seamless, self-updating solution especially useful in dynamic or large-scale deployments.
  • Tip: Parameters allow controlled, manual updating of AMIs without needing to alter the template content every time an AMI changes.
