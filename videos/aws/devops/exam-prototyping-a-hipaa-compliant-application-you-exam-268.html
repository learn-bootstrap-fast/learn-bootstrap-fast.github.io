The correct answer is: Custom rules are created in AWS Config and connected to a Lambda function that incorporates logic for checking compliance. This Lambda function must have permissions to both query AWS Config as well as publish to Amazon SNS.


  • With custom AWS Config rules, you provide a Lambda function that evaluates resource compliance based on your defined criteria. The Lambda function implements the evaluation logic, so it must have both permission to query AWS Config for resource details and permission to send notifications via Amazon SNS (so you can deliver email alerts, for instance).
  • \"After developing your custom rules in AWS Config, you link each Lambda function—containing the compliance logic—with the appropriate custom rule. The custom rule itself must have permissions to both query AWS Config and send notifications to Amazon SNS.\" is incorrect because the Lambda function, not the custom rule, needs these permissions as it is what accesses AWS Config and publishes to SNS.
  • \"You create custom rules in AWS Config and then associate each rule only with one of two AWS-provided Lambda blueprints...\" is invalid. You can associate custom rules with any Lambda function, not just provided blueprints, and you write your compliance logic as needed.
  • \"When adding custom rules to AWS Config, you can only associate each rule with an AWS Lambda blueprint... The rule itself will only require permission to notify Amazon SNS.\" is wrong, since you can connect with any Lambda function (blueprints are just starting templates), and it's the Lambda function—not the rule—that needs to interact with both AWS Config and SNS.
