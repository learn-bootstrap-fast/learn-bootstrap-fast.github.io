The correct choices are Store the application's log output directly in Amazon S3 (Simple Storage Service) and Apply lifecycle policies that transition the logs to Amazon Glacier after three months.

Here’s why:

  • Storing logs in Amazon S3 is best practice for durability and easy access. S3 automatically duplicates data across multiple facilities for maximum protection.
  • Using lifecycle policies to move logs to Glacier leverages S3's ability to archive infrequently accessed data. This is cost-effective and ideal for storing logs after the retention period.

Why the other options are incorrect:

  • Send log data immediately to Amazon Glacier for primary storage as soon as it is generated: Glacier is specifically designed for archival, not for immediate or frequent access. Storing live application logs directly in Glacier makes retrieval difficult and slow, violating best practices for active logs.
  • Set up lifecycle rules to move data to Amazon S3 after keeping it somewhere else for 3 months: S3 should be your initial destination for log data, as it's designed for both storage and ease of management. There’s no AWS feature that moves logs from another storage type into S3 after a set period.

Tip: Always use S3 as your main log repository and schedule transitions to Glacier (or S3 Glacier Deep Archive) for cost savings on long-term data.
