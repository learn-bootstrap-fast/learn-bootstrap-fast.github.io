To troubleshoot a failed AWS CloudFormation stack creation when rollback is disabled, the most effective methods are:

  • Inspect the event history of your CloudFormation stack using the AWS CloudFormation console. The console provides a live timeline of events, status changes, and error messages associated with individual resources in your stack, enabling you to quickly identify which resources failed and why.
  • Examine the instance logs located in /var/log/ on Amazon EC2, focusing on cfn and cloud-init logs, if your problem is related to EC2 resources. If the failure involves Amazon EC2 instances (such as bootstrapping or configuration issues), reviewing the /var/log/cloud-init.log and /var/log/cfn-init.log files on the affected instance can provide detailed steps of what was executed and pinpoint misconfigurations or errors.

The option Leverage AWS Config to trace every API call initiated by your CloudFormation stack is incorrect because AWS Config is designed for configuration tracking and compliance, not real-time debugging of API calls or stack events. Similarly, Enable CloudTrail to track and debug all API operations performed by the CloudFormation stack is not the most practical answer in this scenario. While CloudTrail does record API calls for auditing and security, it lacks context about CloudFormation resource life-cycles and failure reasons; it is not a troubleshooting tool for stack creation issues. For rapid and detailed debugging, rely on the CloudFormation console and resource-specific logs.

Tip: Always utilize the CloudFormation console's Events tab first for high-level troubleshooting, and if your stack provisions EC2 resources, collect logs from the instances for further diagnosis.
