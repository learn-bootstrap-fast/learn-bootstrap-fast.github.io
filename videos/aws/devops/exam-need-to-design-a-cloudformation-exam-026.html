The correct answer is EC2Instance: Type: \"AWS::EC2::Instance\" Properties: InstanceType: !If [CreateProdResources, c1.xlarge, m1.large]. This syntax leverages CloudFormation's Fn::If intrinsic function (or its YAML shorthand !If), which evaluates the CreateProdResources condition. If the condition is true (production), the value c1.xlarge is used for the InstanceType; otherwise (development), it uses m1.large.

Let's review why the other choices are incorrect:

  • EC2Instance: Type: \"AWS::EC2::Instance\" Condition: CreateProdResources Properties: InstanceType: !Ref [c1.xlarge, m1.large] — The Condition attribute is for controlling whether the whole resource is created, not for selecting between values within properties. Also, !Ref with a list is not valid CloudFormation YAML syntax.
  • EC2Instance: Type: \"AWS::EC2::Instance\" Properties: InstanceType: Fn::Not: [CreateProdResources, m1.large, c1.xlarge] — Fn::Not does not select between values; it returns true or false. It's incorrect for dynamically setting InstanceType.
  • EC2Instance: Type: \"AWS::EC2::Instance\" Properties: InstanceType: !Equals [CreateProdResources, c1.xlarge, m1.large] — !Equals only checks for equality and returns a boolean, not a value that can be assigned to InstanceType.

Tip: Use !If when you need to conditionally assign property values; use the top-level Condition only to control resource creation. Review CloudFormation intrinsic functions to understand these differences!
