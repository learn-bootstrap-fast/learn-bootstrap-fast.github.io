Lambda function created in Python 3.6 and Red Hat Enterprise Linux (RHEL) running on on-premises servers are the correct answers.

Explanation:
AWS CodeDeploy supports targeting EC2 instances and on-premises servers using Amazon Machine Images (AMI) (Amazon Linux, Ubuntu, or Windows) or tags, and also supports deployment to Lambda functions and ECS services. However, there are restrictions on how targets can be managed, particularly with tags or instance lists:

  • Lambda function created in Python 3.6: CodeDeploy can deploy to Lambda functions, but these are managed through aliases, not tags or instance lists. You specify the Lambda function and the alias in the deployment, not by tagging them. Thus, you cannot add Lambda functions to CodeDeploy Deployment Groups by tag or instance list.
  • Red Hat Enterprise Linux (RHEL) running on on-premises servers: CodeDeploy can deploy to on-premises instances, but support is for Amazon Linux, Ubuntu, or Windows Server on-premises. RHEL on-premises is not supported as a direct target. Thus, you cannot add RHEL on-premises instances by tags or by instance name to a deployment group.
  • ECS cluster utilizing Amazon Linux AMI: CodeDeploy supports ECS blue/green deployments, so ECS can be used as a deployment target.
  • Auto Scaling group with EC2 instances: EC2 instances in Auto Scaling groups can be tagged and used as targets in CodeDeploy. You can add/tag them in deployment groups directly.
  • Microsoft Windows Server 2016 EC2 instance: CodeDeploy supports Windows Server 2016 as a managed instance, and these EC2 instances can be targeted via tags in deployment groups.

Tip: Always pay attention to what types of deployment groups are supported by AWS CodeDeploy, and how resources are grouped (via tags, lists, or aliases).
