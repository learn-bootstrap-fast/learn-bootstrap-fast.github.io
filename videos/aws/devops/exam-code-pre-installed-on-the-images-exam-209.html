The most economical approach is to use Spot Instances for building AMIs (\"Create a spot instance request with the maximum price set slightly above the current spot price whenever new commits are pushed, set up the instance, and build an AMI from it\"). Spot Instances allow you to leverage unused EC2 capacity at great discounts compared to On-Demand prices, which is ideal for CI workloads that are short-lived and transient.

The option \"Purchase a Light Utilization Reserved Instance for your CI server and consume credits each time you create AMIs on these instances.\" is not suitable because Reserved Instances only provide savings when running instances continuously, which isn't efficient for on-demand, spike-based CI jobs.

\"Have the CI system launch a new On-Demand EC2 instance on each new commit, configure the instance, and then generate an AMI from that instance.\" works technically but On-Demand pricing is higher than Spot, so it's not the most cost-effective strategy.

The option \"On receiving a code push, attach a fresh EBS volume to your CI server, perform all configuration on that volume, then avoid spinning up new EC2 instances to create AMIs.\" misses the point since you still need a running instance to create an AMI, and just swapping EBS volumes doesn't reduce costs meaningfully.

Tip: Spot Instances are ideal when your workload is interruptible and you can handle occasional interruptions or need resources for a short duration. When cost-saving is a primary concern and your AMI builds are not time-sensitive, using Spot Instances offers significant cost reductions.
