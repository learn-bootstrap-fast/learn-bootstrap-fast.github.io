Correct Answers: Utilize AWS Lambda to forward personalized notifications to Slack when a status alteration event from CloudWatch is detected and Configure a CloudWatch Events rule with 'Trusted Advisor' as the event source and select 'Check Item Refresh Status' as the event type.

To automate Slack alerts on Trusted Advisor check changes, you need an event-driven solution that detects changes and sends customized notifications. Setting up a CloudWatch Events rule for Trusted Advisor specifically captures these events, and by triggering an AWS Lambda function, you can customize the notification payload and send it to Slack via a webhook API. This method leverages native AWS integrations and maximizes flexibility for message formatting and routing.

Why other options are incorrect:

  • Set up an SNS topic that will send custom messages directly to a Slack channel via a suitable integration: While SNS can send messages, it does not natively format or transmit notifications to Slack without an intermediary, such as Lambda. SNS lacks direct, robust Slack integration capabilities.
  • In AWS CloudWatch Logs, create a metric filter that looks for new log entries containing 'Check Item Refresh Status': This relies on log streams which may not capture all relevant status change events, and event-driven architecture is more precise than log parsing for this use case.
  • Within Trusted Advisor's Cost Optimization dashboard, establish a notification to an SNS topic upon detection of a new status check event: Trusted Advisor dashboards do not provide direct notification configurations to SNS topics; notifications are handled outside of the Trusted Advisor UI through services like CloudWatch Events (EventBridge).

Tips: Always leverage EventBridge (formerly CloudWatch Events) and Lambda for customizable, third-party notifications such as Slack. SNS is great for email/SMS, but Lambda provides greater control for integrations.
