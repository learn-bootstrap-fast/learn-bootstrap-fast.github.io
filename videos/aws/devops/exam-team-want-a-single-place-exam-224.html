With AWS CloudFormation, configure a CloudWatch Logs group and forward both OS and application logs to CloudWatch using the CloudWatch Logs Agent. is the best solution.

  • This method creates a centralized and scalable logging solution where both the operation and development teams can access logs in a single location (CloudWatch Logs), with the ability to set up granular IAM policies, powerful searching, and alerting.
  • Utilize CloudFormation together with configuration management tools to direct events via UDP toward AWS CloudTrail for remote logging. is incorrect because CloudTrail is designed for API call auditing, not for ingesting custom log data via UDP or any other direct log streams.
  • Arrange for events to be transmitted to an Amazon Kinesis stream and then deliver those logs to either CloudWatch Events or Amazon Redshift depending on which analytics platform is available. is unnecessarily complex for the requirement and does not naturally provide a single consolidated log view as CloudWatch Logs does directly.
  • Leverage AWS CloudFormation to combine application logs with operating system logs and use IAM roles to give both teams permissions to view the output from the EC2 console. is incorrect, as viewing logs directly from the EC2 console is not scalable or efficient, and IAM access to the console doesn't offer centralized logging or analytics.

Tip: Use CloudWatch Logs Agent (or the unified CloudWatch Agent) on each EC2 instance to forward both system and application logs to CloudWatch Logs. This setup makes it easy for teams to access, query, and manage logs securely.
