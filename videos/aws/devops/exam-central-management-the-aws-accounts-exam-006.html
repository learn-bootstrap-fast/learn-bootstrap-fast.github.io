The correct step is to go to the CloudWatch Event console, select Event Buses, and then use Add Permission. Choose Organization and provide the organization ID for the other AWS Organization. This allows all AWS accounts within that organization to send events to your event bus, streamlining permissions for large groups of accounts.

In the CloudWatch Event console, open Event Buses → Add Permission, select Organization, and input the organization ID of the external organization. is correct because it leverages AWS Organizations for scalable permissions, granting all member accounts access rather than configuring individual accounts.

Let's look at why the other options are incorrect:

  • In the CloudWatch Event console, go to Event Buses → Add Permission, select AWS Account, and supply the account IDs of the organization's members. is not optimal because you would need to manage hundreds or thousands of IDs individually, rather than authorizing the organization as a whole.
  • Add an IAM role in your AWS account granting CloudWatch event sending permissions and permitting any account in the organization to assume this role. cannot grant CloudWatch event bus permissions directly; permission to send events is controlled at the event bus level, not via cross-account role assumption.
  • Attach an IAM policy to the CloudWatch Event console that allows all AWS accounts in the organization to send events to your default event bus. is an incorrect workflow—CloudWatch event bus permissions are set in the EventBridge (CloudWatch Events) bus permissions, not by attaching an IAM policy in the console.

Tip: Using the Organization option is the most scalable and easily managed method for cross-organization event bus permissions in AWS EventBridge.
