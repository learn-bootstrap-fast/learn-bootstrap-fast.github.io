Configure two CloudWatch Event rules that each execute on a schedule using cron expressions, then set your Lambda function as the target for each rule and Place the instances in different Auto Scaling groups and configure scheduled scaling actions to adjust desired capacity between 0 and 1 based on the time of day are the correct options.

Explanation:

  • Scheduling the start and stop of EC2 instances based on tags is a common scenario for cost savings in non-production environments. The solution that uses two scheduled CloudWatch Event (now called EventBridge) rules—one for stopping and another for starting—lets you precisely control these actions. By attaching a Lambda function as the target, you ensure only instances with the specified tag are affected. This approach offers flexibility and scalability.
  • Another suitable method is utilizing Auto Scaling groups with scheduled scaling policies. By adjusting the desired capacity to 0 at night (which stops all instances) and setting it back to 1 in the morning (which brings them back up), you achieve the goal without manual intervention per instance, as long as your workload allows for instances to be managed this way.

'Apply two separate Lambda functions: one for stopping and another for starting EC2 instances that have the 'cost-saving' tag' is incorrect because while using Lambda for automation is a part of the solution, the Lambda functions need to be invoked by a scheduling mechanism, such as CloudWatch Events, otherwise the automation aspect is missing.

'Establish an EC2 Savings Plan to automate stopping at 10:00 PM and starting at 6:30 AM for tagged instances' is incorrect as Savings Plans only optimize your billing costs for certain compute usage patterns but do not actually stop and start instances.

'Create a CloudWatch Event rule that triggers periodically using two cron expressions' is misleading wording. Each CloudWatch Event rule supports a single cron or rate expression; two separate rules are required for two schedules (start and stop).

Tip: Always use tags for resource targeting and automation, and ensure your automation functions (like Lambda) have the right permissions to start/stop EC2 instances.
