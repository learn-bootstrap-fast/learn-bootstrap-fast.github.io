The default termination policy in Auto Scaling aims to maintain balance across Availability Zones. The process typically begins by identifying the AZ with the greatest number of instances—here, that's the zone with four EC2 instances. From there, one instance will be terminated in this AZ to help maintain an even distribution. This makes \"Auto Scaling picks a zone with more instances (the AZ with four) and terminates one instance from it.\" the correct choice.

Option \"Auto Scaling identifies unprotected instances closer to the end of the billing hour and terminates those first.\" is incorrect, as the billing hour is only considered as a secondary criterion if there are multiple equally valid candidates in the same AZ.

Option \"Auto Scaling terminates an instance randomly, regardless of zone or configuration.\" is also incorrect—the process prioritizes AZ balancing before random selection.

Option \"Auto Scaling will always remove instances from the group with the oldest launch configuration.\" is not the primary rule since launch configuration age is only considered when balancing and billing criteria don't decide termination.

Tip: Memorize the Auto Scaling default termination sequence: balance AZs → oldest launch config → closest to next billing hour → random choice.
