The best deployment method in this scenario is the Immutable deployment strategy. With this approach, Elastic Beanstalk launches a completely new batch of instances using the new application version, independently of the old ones. Only after these new instances pass their health checks does traffic get directed to them. This method ensures zero-downtime deployments, and in case of failures, makes it easy to revert without impacting the original instances. Additionally, you maintain just one environment and do not need to run two parallel environments at all times.

Why are the other options incorrect?

  • Use a Rolling upgrade to deploy each version gradually to batches in the existing environment, attaching updated instances to the load balancer as they become healthy. – Although Rolling deployments reduce downtime by updating a few instances at a time, there is still a period where both new and old versions are running, which may cause some instability or partial outages if a batch fails. Also, failed health checks can cause a rollback to take longer and potentially impact some users.
  • Select a Rolling with extra batch option that launches an extra set of instances during each deployment for safer and more controlled updates. – While adding an extra batch reduces the likelihood of full-scale downtime, it does not fully isolate the new version from the old like Immutable deployments do. Partial updates still occur in the existing environment, and a faulty deployment could impact some users.
  • Adopt a blue/green deployment by setting up two separate environments and swapping URLs once the new version is verified. – Blue/green deployments fulfill the requirement of only serving traffic after new instances pass health checks, but they require running two environments concurrently, which was explicitly stated as not desired in the scenario.

Tip: Choose Immutable deployments in Elastic Beanstalk when you want zero-downtime updates with the highest level of reliability, health check integration, and simple rollback capability—without the hassle of maintaining two complete environments.
