To transmit logs to an Amazon Kinesis stream, use subscriptions and be sure to indicate the Region when setting up the destination stream. Subscription filters allow CloudWatch Logs to route logs efficiently, and the Region parameter ensures the logs arrive at the correct cross-region destination.

A role-arn is not necessary for AWS Lambda destinations, since CloudWatch Logs can obtain permissions from Lambda's access control settings. This means CloudWatch Logs uses Lambda's execution role, removing the need for a separate IAM role specification.

There is no requirement to specify a role-arn when using a Kinesis stream because the destination owner provides it during stream creation. This is incorrect; when subscribing CloudWatch Logs to a Kinesis stream in another account, you must specify a role ARN granting necessary permissions.

CloudWatch Logs retries data delivery for up to 24 hours if Lambda throws throttling errors. The retry period is actually up to 24 hours for Kinesis and Firehose, but only for a shorter period for Lambda, making this statement misleading.

Subscriptions can deliver log events to Lambda, and the Region must always be set when designating a destination stream. This is partially correct for Kinesis streams and Firehose, but subscription filters sending logs to Lambda do not use a destination data stream or a region identifier parameter.

You can omit providing a role-arn for Lambda endpoints because CloudWatch Logs derives them from the function's settings. While true in substance, this repeats an earlier option, and only applies specifically to Lambda, not to all destinations.
