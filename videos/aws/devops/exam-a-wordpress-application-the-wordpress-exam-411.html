Deploy a MySQL RDS database with Multi-AZ configuration enabled is the best choice to deliver fault tolerance and high availability for a WordPress application using MySQL on AWS. This option automatically provisions and maintains a synchronous standby replica of the database in a different Availability Zone, ensuring that if a failure occurs in the primary AZ or database instance, RDS will seamlessly promote the standby to become the new primary. This failover process is automatic and requires no manual intervention, minimizing downtime and service interruption.

The option Set up MySQL on several EC2 instances located in different Availability Zones and enable replication between them using custom scripts could achieve some level of redundancy but introduces considerable manual management overhead, potential consistency issues, and does not provide seamless failover or automated monitoring. The option Install MySQL on multiple EC2 hosts within a single Availability Zone and implement replication by scripting still risks loss of availability if the entire AZ fails, which does not meet the fault tolerance requirement. Finally, Launch a MySQL RDS instance and create a Read Replica boosts read performance and availability for reads, but does not offer automatic failover or full multi-AZ redundancy for write operations, as the Read Replica is promoted only through manual intervention and primarily used for read scaling.

Tip: Use RDS Multi-AZ deployments for production workloads requiring high availability, automatic failover, and minimal management overhead. Choose Read Replicas for performance scaling, not for high availability. Manual EC2-based MySQL clusters require significant effort to match RDS Multi-AZ’s automated features.
