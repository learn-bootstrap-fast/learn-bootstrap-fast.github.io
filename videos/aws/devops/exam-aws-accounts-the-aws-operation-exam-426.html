The correct configuration is to Select a custom image and specify the ECR image registry, then provide the full ECR URI from the other AWS account. CodeBuild allows you to directly reference Docker images stored in another AWS account’s ECR repository, provided that you grant the correct permissions (such as repository access and the appropriate resource policies for cross-account usage), and you specify the full ECR repository URI. This streamlines the process and avoids duplicating images between accounts.

Why the other choices are incorrect:

  • Pick the AWS managed Ubuntu image and configure it to pull the Docker image from the other account's ECR during the build process. — This solely uses an AWS managed image as the environment, not the custom ECR image you are required to use for the build environment itself, so it doesn't meet the requirement.
  • Opt for using a custom image and choose 'Other registry' for an external Docker registry, using the other account's ECR URI as the registry endpoint. — ECR is not classified as an 'External Docker registry' in this context; you should instead select the ECR image registry option to properly authenticate and use AWS ECR resources.
  • Since CodeBuild cannot use Docker images from an ECR in another AWS account, copy the image into your own account's ECR repository first. — This is incorrect as CodeBuild does support cross-account usage of ECR images if the right permissions are in place, so copying is unnecessary.

Tip: For cross-account ECR access, always ensure that both the CodeBuild project has permissions to pull the image (by assigning the correct IAM role) and the ECR repository policy in the source account allows access from the target account. This enables you to maintain a single source of truth for your Docker images across AWS organizations.
