The correct choice is UpdateReplacePolicy. This resource attribute ensures that when an AWS resource is replaced during an update (for example, if the properties of an AWS::RDS::DBInstance require replacement), the original resource is retained according to the specified policy, such as Retain. This is particularly useful to avoid accidental deletion of critical resources like databases, as specified in the scenario.

Here's why the other answers are incorrect:

  • DeletionPolicy: While this attribute also controls what happens to a resource when it is deleted from the stack, DeletionPolicy only applies when the stack itself is deleted or the resource is explicitly removed from the template — not on replacement due to an update. Therefore, it does not solve the scenario described.
  • UpdatePolicy: This attribute is used for update operations, but only for certain resources (like Auto Scaling groups or Elastic Beanstalk environments). It does not control what happens to a resource during a replacement update for RDS instances.
  • CreationPolicy: This is used to indicate that AWS CloudFormation should wait for some condition (like a signal) before marking the resource as created. It does not affect how resources are handled during replacement.

Tip: Use UpdateReplacePolicy with values such as Retain, Snapshot, or Delete for finer control over resource lifecycle in update scenarios. Make sure to set it explicitly in your template when resource retention during replacement is required.
