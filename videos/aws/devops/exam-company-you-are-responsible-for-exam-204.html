The best strategy here is to use a parameter in the CloudFormation template along with a Condition clause to control resource creation based on environment. You can define a parameter—for example, EnvironmentType—and then use conditions to create the S3 bucket only when the value is set to 'development'. This approach maximizes reusability and reduces template duplication.

'Build separate CloudFormation templates for development and production environments individually.' is incorrect because it increases maintenance overhead by duplicating templates, making updates more cumbersome.
'Leverage the CloudFormation metadata section to determine if an S3 bucket should be launched based on the environment.' is also incorrect, as the Metadata section is intended for supplementary information and does not control the creation of resources.
'Pre-create an S3 bucket manually and restrict access to it using tags defined in the CloudFormation template.' doesn't dynamically manage resource creation within CloudFormation; manual steps break automation and governance.

Tip: Using parameters and conditions is the preferred AWS best practice for environment-specific resources. This not only keeps your template DRY (don't repeat yourself), but also limits the risk of drift and errors.
