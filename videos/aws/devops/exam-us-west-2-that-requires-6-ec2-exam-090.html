Distribute 3 instances in us-west-2a, 3 in us-west-2b, and none in us-west-2c and Run 2 instances in each AZ: us-west-2a, us-west-2b, and us-west-2c are both correct ways to ensure 100% fault tolerance in this scenario.

  • Why these are correct: In the event of any single Availability Zone (AZ) going down, at least 6 instances would remain running because the minimum number hosted outside any one AZ meets your application's requirements. By either splitting 3 and 3 across 2 AZs or 2, 2, and 2 across all 3 AZs, EC2's Auto Scaling can replace lost instances quickly, keeping required capacity running in healthy AZs.
  • Allocate 4 instances to us-west-2a, and 2 each to us-west-2b and us-west-2c. is not correct, because if us-west-2a fails, only 4 instances are left (2 each in 2b and 2c).
  • Deploy 6 instances both in us-west-2a and us-west-2b; none in us-west-2c. is wasteful and doesn't help maximize fault tolerance among all AZs. Plus, if either AZ fails, you'd still only have 6 (not more) running, and allocating 0 to the third AZ reduces redundancy.
  • Place 3 instances in each AZ: us-west-2a, us-west-2b, us-west-2c. provides the appearance of redundancy, but with 9 total instances, it's more costly than needed. If any one AZ fails, there would still be 6 running, but this sacrifices cost-effectiveness.

Tip: For maximum AZ fault tolerance, make sure that the total required capacity is met even if you lose an entire AZ. Divide the instances so that the sum in the surviving AZs always meets or exceeds your minimum requirement. Avoid putting a majority of instances in a single AZ.
