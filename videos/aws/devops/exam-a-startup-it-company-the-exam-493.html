The correct answer is Configure an S3 Cross-Region Replication policy on the CloudTrail log bucket to copy logs to another bucket located in a different region.

Explanation:
Cross-Region Replication (CRR) for Amazon S3 buckets ensures the automatic and continuous copying of CloudTrail logs from their source bucket in one region to a target bucket in another region. This provides redundancy and disaster recovery capabilities: even if an entire region fails, critical audit trails and security information remain accessible in a separate region, protecting the organization from data loss.

Here's why the other options are not appropriate:

  • Turn on SSE-KMS encryption for the S3 bucket holding CloudTrail logs. — While encryption is important for securing data at rest, enabling SSE-KMS does NOT address regional outages or improve availability in the event of a disaster affecting the entire region.
  • Add a new S3 bucket in another AWS region directly from the CloudTrail console as an additional destination for the trail. — CloudTrail trails can only be configured with one destination S3 bucket per trail; you cannot specify multiple buckets (especially in different regions) directly from the console. This is a common misconception.
  • Deploy an AWS Lambda function that reads log files from the trail S3 bucket and manually copies the logs to another bucket in a different AWS region. — Although technically possible, this is a much more complex, less reliable, and less automated approach compared to simply using S3's built-in cross-region replication feature.

Tip: Use S3 Cross-Region Replication for critical log and audit data to enhance durability and compliance, especially when regional disasters or AWS region outages are a concern.
