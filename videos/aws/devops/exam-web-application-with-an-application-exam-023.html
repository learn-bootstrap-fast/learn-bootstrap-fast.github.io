The correct approach is to edit the target group associated with your ECS cluster's Application Load Balancer and set the Deregistration delay to 600 seconds (10 minutes). The Deregistration delay defines how long the load balancer will wait for in-flight requests to complete after a target is deregistered. This setting ensures the old task is given a 10-minute window to drain connections before termination, matching your updated requirement.

Why the other options are incorrect:

  • Access the Application Load Balancer attached to your ECS cluster in the AWS Console and change the default value of the connection draining timer from 5 to 10 minutes. – Connection draining is actually managed via the target group settings, not directly on the load balancer resource.
  • Use the ECS CLI command ecs-cli compose with the parameter --Deregistration delay=600 to extend the connection draining duration to 10 minutes. – The ECS CLI does not offer a --Deregistration delay parameter for controlling the ALB draining timeout during deployments.
  • Navigate to the ECS service settings in the AWS Console and adjust the connection draining timeout in the Deployment tab from 5 minutes to 10 minutes. – ECS service console settings do not expose a connection draining timeout for Application Load Balancers; this is configured within the target group.

Tip: Always configure the connection draining or deregistration delay where it is managed; for ALB, this is specifically within the target group settings.
