The best practice is to create a dedicated IAM user for the auditor with read-only access to VPC resources, and share these credentials. This ensures the auditor has only the permissions required for their tasks—viewing security groups and network ACLs—while minimizing security risks associated with excessive privileges.

  • Assign the auditor an IAM user account that is associated with an administrator role, and enable multi-factor authentication for enhanced protection. — Although MFA increases security, administrator access is far too broad for an auditor's needs, violating the principle of least privilege.
  • Allow the auditor to use the root account credentials for your AWS environment since full access is required for the audit. — Never share or use root credentials except for very specific tasks. This option introduces severe security risks and is never recommended.
  • Set up an IAM user with complete VPC permissions, but configure a condition restricting modification capabilities unless requests originate from the auditor's IP address. — While IP restrictions add security, providing full access (even conditionally) is not justified for a read-only requirement. Least privilege and the need-to-know basis should always be enforced.

Tip: Always assign permissions following the least privilege principle and avoid giving excessive access. For auditors, a custom policy with read-only rights to just the needed AWS resources is ideal.
