The correct answer is: Associate distinct tags to your test and production EC2 instances, and implement IAM policy conditions that grant permissions only for instances with authorized tags.

This solution leverages resource-level permissions in AWS. By tagging EC2 instances (for example, with Environment: Production or Environment: Development), you can write IAM policies that use these tags as conditions, restricting users or groups to only operate on resources with matching tags. This ensures proper segmentation and least privilege, and is highly scalable and flexible for permissions management.

  • Deploy your test and production instances in separate VPCs, and connect them with VPC peering. – This option separates network boundaries but does not address IAM permission boundaries. VPC peering is for connectivity, not fine-grained access control. It doesn't prevent a user with sufficient IAM rights from accessing instances in either environment.
  • Configure an IAM policy with conditions to allow actions only on instances designated for production or development use. – While this option sounds close, it is ambiguous without referencing how resources are distinguished. In AWS, the common and scalable way to differentiate is by using resource tags.
  • Launch test and production instances in separate Availability Zones and enforce Multi-Factor Authentication for access. – Separating by Availability Zones does not isolate access at the instance or user level. MFA improves authentication security but does not help with segmentation between production and test resources.

Exam Tips: Always use tagging and IAM policy conditions for fine-grained access control on AWS resources. This is a core security best practice and strongly favored in the exam when segmentation is required.
