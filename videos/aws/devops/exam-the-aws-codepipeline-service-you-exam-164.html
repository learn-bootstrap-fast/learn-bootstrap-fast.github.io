The most effective solution is to set up user parameters within the new CodePipeline stage and extract the parameter from the JSON event object sent to Lambda by CodePipeline. This method allows the pipeline to send dynamic values, like a new URL each time, that the Lambda function can then retrieve from the incoming event payload (event['ParameterName'] in Python).

  • \"Include the parameter in the new CodePipeline stage and access it within the Lambda function as an environment variable\" is not suitable, because environment variables are static and set at Lambda deployment time, not dynamically for each invocation from CodePipeline.
  • \"Have an API Gateway accept the parameter as a query string and relay it to the Lambda function\" is unnecessarily complex and introduces extra components (API Gateway) when CodePipeline natively supports parameter passing to Lambda actions.
  • \"Deploy a CloudFormation stack via the Lambda function and pass the parameter from CodePipeline to CloudFormation using the !Ref intrinsic function\" is not aligned with the use case. Invoking a CloudFormation stack isn't needed just to pass runtime parameters to a Lambda invoked directly from CodePipeline.

Tip: To pass parameters dynamically from CodePipeline to Lambda, utilize UserParameters in the pipeline’s Lambda action configuration. This keeps your solution straightforward and maintainable.
