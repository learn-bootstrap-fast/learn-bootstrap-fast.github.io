The correct statement is: For the Amazon Linux OS, Elastic Beanstalk only lets you use the yum package manager within the Packages section. RubyGems isn't supported.

Elastic Beanstalk supports several package managers in its configuration files depending on the underlying platform. For Amazon Linux, only yum and a few others (like rpm) are supported in the Packages section, but not RubyGems. If you want to install Ruby gems, you need to do so using commands or container_commands sections instead of directly via the Packages block.

  • Elastic Beanstalk enforces that only one type of package manager (either yum or RubyGems) is allowed per config file, meaning you'll need separate files for each manager. – This is not correct because you can include multiple package manager blocks in a single YAML config file if the platform supports them.
  • Within a given package manager, the sequence in which packages are installed in the config file is not guaranteed. – This is misleading, as the install order within the same package manager is not always guaranteed, but the main limitation here is on manager support, not sequencing. This is not the most direct or relevant answer for this scenario.
  • The configuration only installs the newest available version of a package and does not let you specify exact versions in the file. – This is incorrect; you can specify the desired package version in the config file with the syntax package: version in the Packages section.

Tip: Always double-check the documentation for the list of supported package managers for your chosen Elastic Beanstalk platform. If a package manager isn't supported natively, use custom commands or scripts in other config file sections.
