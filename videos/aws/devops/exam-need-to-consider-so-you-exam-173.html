To provide SSO access from your corporate AD or LDAP directory to AWS resources while restricting each user’s S3 access to their own folder, you should:

  • Set up a federation proxy or identity provider for SSO: This enables authentication against your corporate identity store, such as AD or LDAP, rather than managing AWS credentials separately. It streamlines sign-in and centralizes control.
  • Use AWS Security Token Service (STS) to issue short-lived credentials: STS allows temporary IAM credentials to be provided to users upon successful authentication via the identity provider. This improves security since credentials are automatically rotated and reduce the risk of long-lived key misuse.
  • Assign an IAM role to map each authenticated AD/LDAP user to permissions for their folder: By dynamically granting users the appropriate IAM role, you can define S3 policies that allow access only to their respective folders, ensuring fine-grained security controls.

The option \"Apply specific tags to every folder within the S3 bucket for user-based access\" is incorrect, as S3 folder-level access is best controlled via IAM policies and S3 prefixes, not by tagging folders (since tags are typically used for resources, not S3 prefixes/folders). \"Ensure each user has a matching IAM user account in AWS for access control\" is also inefficient and undermines the benefit of SSO and federated identity as it requires duplicating user management in AWS, increasing administrative overhead. The recommended method leverages federation, roles, and STS for secure, centralized, and scalable access management.

Tip: When integrating SSO for temporary access, always use federation and STS with roles; avoid creating individual IAM users for each directory user.
