The best way to guarantee license compliance—where software must remain on specific physical servers—is to use Dedicated Hosts. Dedicated Hosts allow you to allocate distinct physical servers to your account, and let you control which EC2 instances are deployed on those servers by specifying Host IDs in your CloudFormation template. This ensures that redeployed instances always use the exact physical machines, meeting strong licensing requirements.

Define a custom VPC, set its instance tenancy to dedicated, and update the CloudFormation template to launch EC2s within it. is incorrect because while dedicated tenancy at the VPC level provides hardware isolation from other customers, AWS controls the underlying hosts and cannot guarantee the same host is chosen during stack redeployments.

Configure the CloudFormation EC2 resource for 'dedicated' tenancy so EC2 instances run as dedicated instances for the customer. does offer dedicated hardware, but, like the previous choice, does not ensure subsequent EC2 launches are placed on the same physical host—this also fails the license binding requirement.

In your CloudFormation template, define an AWS::EC2::Host resource to gain a 100% dedicated server for your application's EC2s when they launch. is misleading: merely allocating a Dedicated Host is only part of the solution; you also need to ensure your launched EC2s are specifically tied to that Host by referencing its Host ID, as in the correct answer.

Tip: When third-party licensing requires strict host affinity, always prefer Dedicated Hosts with explicit Host ID affinity in your templates. Know the subtle but critical differences between dedicated instances, dedicated tenancy, and Dedicated Hosts for the exam.
