The most effective and scalable approach in this scenario is to use Trusted Advisor’s Cost Optimization Checks to review Low Utilization EC2 Instances. Trusted Advisor provides a built-in, cross-account analysis focusing especially on cost-saving opportunities and will automatically list EC2 instances with consistently low utilization (e.g., CPU usage lower than 10% over 14 days), simplifying identification and mitigation efforts across multiple accounts.

The other options have significant limitations: Establish CloudWatch Metrics alarms for each instance and configure notifications via SNS for CPU usage of less than 10% would require a high level of manual overhead, as each instance would need its own alarm and the alarms must be properly configured and maintained across accounts. Set up an AWS Lambda function to periodically assess each instance's average CPU utilization and alert through SNS if sustained usage is low could be automated, but maintaining a custom function at scale adds complexity, requires secure cross-account access, and essentially duplicates what Trusted Advisor already delivers out-of-the-box. Utilize CloudWatch Logs to implement a filter that monitors EC2 usage rates, setting up an alarm if utilization falls below the threshold is not natively suitable, as CloudWatch Logs are not intended for tracking instance metrics like CPU utilization; instead, metrics should be handled with CloudWatch Metrics.

Tip: Trusted Advisor’s Cost Optimization features are the most efficient way to manage resource usage and identify cost-saving opportunities, especially in complex, multi-account AWS environments.
