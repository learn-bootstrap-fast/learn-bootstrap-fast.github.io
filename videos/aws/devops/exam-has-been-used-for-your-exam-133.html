The correct answer is option C: Upgrading your environment to a load-balanced, autoscaling setup and specifying a scaling policy (average CPU utilization >85% for 5 minutes) will enable Elastic Beanstalk to add or remove EC2 instances as traffic fluctuates, preventing resource exhaustion.

Why other options are incorrect:

  • Switch the environment’s configuration to a highly available mode by setting up autoscaling with multiple EC2 instances based on memory consumption: While moving to a highly available environment and using autoscaling is beneficial, Elastic Beanstalk natively supports autoscaling triggers based on CPU metrics, not Memory utilization, and configuring memory-based scaling requires additional steps outside the standard console interface.
  • Terminate the current environment and create a new one configured for multiple instances, since the existing setup can't be changed to support autoscaling: This is wrong because Elastic Beanstalk allows you to convert a single-instance environment to a load-balanced, autoscaling one without recreating the environment, minimizing downtime and manual effort.
  • Edit the capacity settings to a load-balanced environment and enable all availability zones. Then add a scaling event based on the median CPU utilization exceeding 85% for 1 minute: Although this option correctly implements load balancing and AZ selection, using median CPU utilization and such a short timespan (1 minute) are not best practices. Average CPU utilization for a longer evaluation period is preferred for stable, effective scaling.
  • Change the EC2 instance type to t2.large to meet your higher CPU and memory demands: Upgrading the instance type may temporarily help but doesn't address the root need for scaling out. Load balancing and autoscaling are necessary for high availability and performance under varying loads.

Tip: In Elastic Beanstalk, always look to leverage autoscaling and load balancing for workloads that may experience fluctuating or unpredictable traffic for best resilience and capacity management.
