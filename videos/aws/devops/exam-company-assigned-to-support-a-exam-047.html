The most effective solution is the architecture described in Implement a Step Functions state machine that coordinates workflow actions through individually purposed Lambda functions. Set the CodePipeline deploy action to trigger a Lambda function that serves as an intermediary between the pipeline and the Step Functions state machine. Enable logging for the state machine to send execution logs to Amazon CloudWatch Logs.

Why this approach is correct: This method leverages AWS Step Functions for orchestrating complex, asynchronous workflows by composing several single-purpose Lambda functions, promoting maintainability and clear separation of concerns. By placing a Lambda function as a decoupling layer between CodePipeline and Step Functions, you keep the pipeline modular and more flexible. Crucially, Step Functions natively supports integration with Amazon CloudWatch Logs, making it straightforward to set up centralized logging for workflow execution histories—with no need for custom exports or unrelated log storage patterns.

Why the other options are incorrect:

  • Design an AWS Lambda function dedicated to handling workflow actions. Make the CodePipeline deploy action invoke this single Lambda function directly. To centralize logs, configure an Amazon S3 bucket to store log exports coming from Amazon CloudWatch Logs.: This solution underutilizes orchestration capabilities; a single Lambda function can become complex and hard to maintain as workflows grow. Logging to S3 from CloudWatch Logs is unnecessary when direct, granular logging to CloudWatch is available through Step Functions.
  • Build a Lambda function to address all workflow actions. Configure CodePipeline to trigger this Lambda function directly for deploy actions. Use an Amazon S3 bucket to directly collect all logs generated by the Lambda function.: Merges all workflow actions into one Lambda, which is against best practices for serverless orchestration, reducing clarity and flexibility. Storing logs directly in S3 also loses the advantages of native CloudWatch integration, visualization, and monitoring.
  • Set up a Step Functions state machine using specialized Lambda functions for each discrete workflow action. Have the CodePipeline deploy action invoke a Lambda function that separates the state machine logic from the pipeline. Use an S3 bucket for centralized logging as Step Functions cannot integrate with CloudWatch Logs.: Incorrect because Step Functions does support logging to CloudWatch Logs natively; stating otherwise is factually wrong. Utilizing S3 in this context introduces unnecessary complexity and loses built-in observability and analytics features.

Tip: Always use Step Functions for coordinating complex and asynchronous workflows in AWS, and take advantage of its direct integration with CloudWatch Logs for auditability and troubleshooting.
