Use Amazon Inspector to run an assessment with the 'Security Best Practices-1.0' rule package, which can verify if root login and password-based SSH authentication are disabled. This is the most straightforward method because Amazon Inspector is designed for automated security assessments, offers a simple setup, and targets best practices for EC2 instances, including SSH settings.

Set up an AWS Config rule to validate that password authentication and root SSH login are deactivated for EC2 instances, triggering an SNS alert if a non-compliant resource is detected. is incorrect because AWS Config lacks the direct capability to access or evaluate OS-level configurations such as SSHD settings within EC2 instances. Config rules typically assess resource configurations available via AWS APIs, not detailed in-instance files.

Limit deployments to EC2 instances using only official Amazon Linux AMIs, since these by default have root SSH login and password authentication disabled. is not a sufficient solution on its own. While these AMIs are secure by default, post-deployment changes on running instances or use of alternative AMIs could reintroduce security risks. There must be consistent, automated validation.

Develop a Lambda function that iterates through all Linux instances and manually checks /etc/ssh/sshd_config to confirm SSH root login and password authentication are both off. is possible but significantly more complex and less scalable. Custom scripts require ongoing maintenance, secure instance connectivity, and error handling, making this approach more difficult compared to using built-in AWS tools like Inspector.

Tip: Leverage native AWS security and compliance tools like Inspector for ongoing assessments of instance-level configuration. Inspector is designed to check a range of best practices and requires much less effort than developing and maintaining custom code. Always verify what each AWS management tool is capable of checking, as not all can assess configurations inside operating systems.
