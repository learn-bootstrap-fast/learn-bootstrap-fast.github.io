The Let users provide the AMI ID through a parameter when launching the stack, ensuring the parameter type is set as AWS::EC2::Image::Id option is the most robust and best practice approach. Setting the parameter type to AWS::EC2::Image::Id enables built-in validation from AWS and improves input accuracy.

Include a mapping under Resources for all possible AMI IDs, then use the FindInMap intrinsic function to select the correct ID is unnecessarily complex for a single region scenario, and the mapping should not be under Resources but a top-level Mapping section. Simply add a Parameters section that allows input of the AMI ID is incomplete without specifying the correct parameter type, which offers additional validation. Specify the parameter as a String, and validate with min/max length and other restrictions gives limited protection and doesn’t benefit from AWS’s built-in resource type validation. Create a mapping for available AMI IDs in all regions and use FN::FindInAMI within the Resources to reference the AMI is invalid, as there is no such intrinsic function called FN::FindInAMI (the function is Fn::FindInMap).

Tip: For CloudFormation templates, use those specialized parameter types (like AWS::EC2::Image::Id) for user input whenever possible to leverage AWS resource validations. Avoid overcomplicating templates when only one region is involved.
