The optimal solution is to define a CloudFormation StackSet targeting your Organizational Unit and required regions. CloudFormation StackSets were designed for precisely this scenario: they let you centrally deploy CloudFormation templates to multiple accounts and regions simultaneously, leveraging your AWS Organization structure for streamlined governance. By selecting an entire OU, the StackSet will automatically propagate the stack to all accounts under that OU and adapt dynamically as accounts are added or removed.

The option Set up an AWS CodePipeline workflow with a source stage to select your CloudFormation template, followed by a deploy stage to launch the template in each account within the organizational unit is incorrect because CodePipeline alone lacks native orchestration across multiple AWS accounts and OUs. You would need significant custom code or manual intervention to target every account, making this approach less scalable and harder to maintain.

The suggestion Ensure the CloudFormation template includes parameters for specifying target AWS accounts and regions, and then use the management account to deploy the stack across these accounts is also not ideal, as CloudFormation doesn't allow cross-account stack deployment simply by listing accounts as parameters. Each stack must be deployed within the context of its target account, not centrally from the management account.

The idea of creating an IAM role that grants permission to create Config rules in accounts belonging to the Organizational Unit, then using this role within a CodeDeploy task to roll out CloudFormation stacks into all relevant accounts is unnecessarily complex. CodeDeploy is mainly for application and code deployment rather than infrastructure as code across multiple accounts, and coordinating roles and permissions across all accounts adds another layer of complexity.

Tips: For large multi-account AWS environments, always look for native multi-account deployment tools like CloudFormation StackSets, which can automatically integrate with Organizational Units for widespread, secure, and repeatable infrastructure deployment.
