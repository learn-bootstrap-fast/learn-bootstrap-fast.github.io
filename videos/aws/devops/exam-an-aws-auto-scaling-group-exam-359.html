The best answer is Revise your CloudFormation template to specify the new C3 instance type in the launch configuration, then add an UpdatePolicy to the Auto Scaling group for a rolling update procedure before updating your stack with the new template.

This approach leverages AWS CloudFormation’s support for change management and minimal disruption. By integrating the UpdatePolicy attribute (such as AutoScalingRollingUpdate), CloudFormation can orchestrate a rolling replacement of instances, ensuring only a limited number of instances are replaced at one time, thus minimizing downtime and impact to users.

Here's why the other options are less suitable:

  • Copy the current launch configuration in the AWS Management Console, select the C3 instance type in your new launch configuration, and then assign it to the Auto Scaling group, which will change all running instances to the new type instantly. – While you can assign a new launch configuration, Auto Scaling will only use it for new or replaced instances. Existing instances will not be automatically updated; you would need to manually trigger instance replacement. This approach does not guarantee minimal downtime and doesn't integrate with IaC best practices.
  • Modify your CloudFormation template by changing the instance type to C3 in the launch configuration, then perform a stack update, allowing Auto Scaling to replace instances one by one with the new type. – This lacks the explicit use of the UpdatePolicy attribute. Without it, a stack update may cause replacement of all instances at once, leading to higher downtime for users.
  • In the AWS Console, simply alter the existing launch configuration to use the C3 instance type and perform a rolling update within the Auto Scaling group. – Launch configurations in AWS cannot be edited once created; you need to create a new one. Additionally, this process bypasses CloudFormation, breaking your infrastructure-as-code consistency and potentially causing configuration drifts.

Tip: Always use the UpdatePolicy in your CloudFormation stack when you need to perform updates with minimal downtime, especially with Auto Scaling groups.
