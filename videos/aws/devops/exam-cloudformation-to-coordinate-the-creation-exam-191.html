The correct answers are AWS::CloudFormation::WaitCondition and CreationPolicy attribute.

  • The AWS::CloudFormation::WaitCondition resource is specifically designed to pause the stack creation process until a signal is received (for example, from an instance or application startup script), which helps coordinate resource provisioning that might depend on asynchronous tasks finishing first.
  • The CreationPolicy attribute is used within resource definitions (typically for EC2 instances or AutoScaling groups) to instruct CloudFormation to wait for a specified number of signals before declaring a resource creation a success. This allows you to ensure a provisioned EC2 instance is properly initialized before continuing with the rest of the stack deployment.
  • AWS::CloudFormation::HoldCondition is an invalid resource type and does not exist in CloudFormation.
  • HoldPolicy attribute is not a supported or recognized attribute within CloudFormation templates.

Tip: Proper synchronization of stack resources avoids race conditions and errors in infrastructure setups. Use CreationPolicy when you need to verify initialization steps, and WaitCondition for scenarios where inter-resource dependencies exist.
