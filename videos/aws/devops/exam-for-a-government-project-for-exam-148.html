The Set up dedicated hosts specifically for this application so EC2 instances can reliably run on the same physical hardware. In your CloudFormation, provide the HostID and declare tenancy as dedicated host. option is correct. Dedicated Hosts allow you to control which physical server your EC2 instances run on. This ensures that third-party software licenses that bind to CPUs or physical servers remain valid after stack redeployments, since instances can be launched on the same dedicated host each time by specifying the HostID. This is exactly suited for scenarios requiring license compliance with hardware-based enforcement.

Why the other choices are incorrect:

  • Configure the CloudFormation template to allocate AWS::EC2::Host resources for dedicated physical servers when launching EC2 instances.: Merely allocating dedicated hosts does not ensure EC2s are consistently placed on the same hosts across redeployments. You need to explicitly assign instances to existing HostIDs for license persistence.
  • Specify the EC2 instances in CloudFormation as dedicated instances by setting the tenancy value to dedicated.: Dedicated instances utilize hardware dedicated to a single customer, but AWS may place them on different physical servers with every launch. That doesn’t satisfy the requirement to use the same server after redeployments.
  • Provision a custom VPC with the instance tenancy attribute set to dedicated and update the CloudFormation template to launch EC2 instances from this VPC.: This configures all EC2s in a VPC as dedicated instances, but doesn’t guarantee which physical host the VM is assigned to during redeployment. Thus, this does not meet license requirements tied to a specific piece of hardware.

Tip: Use Dedicated Hosts for physical server affinity, especially when required for licensing or regulatory reasons.
