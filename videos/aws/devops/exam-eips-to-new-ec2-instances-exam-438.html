The correct way to resolve hitting the Elastic IP (EIP) limit is to Send a request for an Elastic IP quota increase using the AWS Service Quotas dashboard. This is the standard AWS workflow for raising service quotas, and it enables you to request a specific increase beyond the default (typically 5 EIPs per region). This is quick and effective, and changes can be tracked from the console.

The option Go to AWS Trusted Advisor, review EIP usage, and increase the EIP limit directly within Trusted Advisor is incorrect because Trusted Advisor provides recommendations and usage data, but does not support directly making quota requests. Submit an AWS support ticket to raise your EC2 Elastic IP limit from 5 to 30 used to be the method before Service Quotas, but now AWS recommends using the dedicated Service Quotas console for most quotas. Elastic IP quota is fixed; instead, alter your provisioning script to use either public or private IP addresses rather than EIPs is incorrect, since the EIP limit is adjustable and you do not need to re-engineer your automation for larger environments.

Tip: When scaling in AWS, always check service and resource limits before deploying at scale, especially with resources like EIPs that have a low default quota, and use the Service Quotas console for increases.
Trick: You may encounter legacy suggestions about submitting support tickets for certain limits, but Service Quotas is now the standard for most quota requests.
