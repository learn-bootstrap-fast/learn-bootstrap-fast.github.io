Implement an AWS Config rule to evaluate whether CloudFormation stack resources have drifted from their template definitions. If the rule detects NON_COMPLIANT status, notify the team using an SNS topic is the most suitable solution. AWS Config offers managed rules that can monitor configuration drift within CloudFormation stacks, allowing for automatic compliance checking and integrated notification. This enables proactive and automated detection and alerting without needing custom scripts or polling logic.

Let’s review why the other alternatives are not ideal:

Configure a Lambda function to periodically check each CloudFormation stack for configuration drift every ten minutes, and if drift is detected, use AWS SES to notify the team by email. – While this could work, it requires building and managing a custom Lambda function and scheduler, which is more complex and less reliable than native drift detection features.

Set up a CloudWatch Events rule to monitor all CloudFormation stack events, and use SNS to trigger an email alert for any event related to CloudFormation. – CloudWatch Events do not specifically filter drift events, so this would generate unnecessary alerts for routine stack activity, making it difficult to distinguish actual drift cases.

Activate CloudTrail and use a Lambda function to parse CloudTrail logs, sending an email whenever stack resources are found to have been changed outside of CloudFormation. – Parsing CloudTrail logs for drift detection is cumbersome, not real-time, and could miss relevant changes. It also requires considerable custom development.

Tip: Using AWS Config managed rules makes drift detection simpler and builds in automated notification and compliance tracking.
