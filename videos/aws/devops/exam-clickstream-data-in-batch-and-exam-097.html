The CloudFront with access logs to S3, processed by EMR solution is most suitable for this scenario. This architecture capitalizes on highly scalable, managed AWS services: CloudFront provides low-latency, global edge collection and generates access logs in S3—no per-request storage is required, and logging is robust and scalable. EMR jobs are cost-effective for batch processing, especially because reports are only generated weekly, not requiring near-real-time data access.

The option to use RedShift with Lambda is less optimal as Redshift clusters are costly at high scale and not inherently designed for sudden, massive ingest bursts (which are better handled by S3 or Kinesis for write scalability). Elasticsearch with Auto Scaling Groups focuses on real-time analytics and dashboards, but operational overhead, cost, and write scaling challenges make it less appropriate for infrequent reporting. The Kinesis-based solution is effective for near-real-time streaming and analytics rather than batch, weekly aggregation, and introduces more moving parts (Kinesis, Lambdas, Spark streaming), which can increase complexity and cost for a once-a-week reporting requirement.

Tip: For infrequent, high-scale batch analytics, leveraging S3 storage and scheduled compute jobs (like EMR or Athena) is often more cost-effective than always-on or streaming analytics systems. Additionally, CloudFront is ideal for capturing global click data efficiently with built-in log delivery to S3.
