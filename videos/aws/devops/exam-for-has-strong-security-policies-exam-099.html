The right answer is You should configure a new CloudTrail and specify an S3 bucket for log storage. By default, CloudTrail will begin logging all relevant CloudFormation API calls, providing details useful to the security team.

Explanation: CloudTrail provides comprehensive logging for management events including AWS CloudFormation API calls without requiring any additional configuration—CloudFormation API events are part of the default set. This makes it possible for your security team to review all creation, update, and deletion actions performed via CloudFormation. Logs are delivered to your designated S3 bucket, helping support audit and compliance needs.

'AWS CloudTrail does not log CloudFormation-specific API calls. It only keeps records of API events for resources managed or created by CloudFormation, but not the CloudFormation service itself.' is incorrect because CloudTrail does indeed capture CloudFormation API events such as stack creation, updates, and deletions.

'A new CloudTrail with a designated S3 bucket is required, and you must explicitly include CloudFormation as the service for tracking. CloudTrail logs will show full details such as IAM roles, tags, parameter names, and parameter values for every stack operation.' is incorrect—while you need to set up CloudTrail and an S3 bucket, CloudFormation API calls are tracked by default; you don't need to explicitly specify the service. Also, CloudTrail captures details about the calls, but not always every single parameter or tag unless included in the API request, and sensitive value logging can be limited.

'It is best to use AWS Config to track CloudFormation API operations since it provides monitoring for actions such as creating, updating, or deleting stacks.' is incorrect because AWS Config is primarily for resource configuration tracking and compliance, not for detailed auditing of API calls. It complements CloudTrail but does not replace the audit logs of API-level operations.

  • Tip: Use CloudTrail for logging API calls across AWS services, and AWS Config for resource configuration tracking. Combining both offers stronger security visibility.
