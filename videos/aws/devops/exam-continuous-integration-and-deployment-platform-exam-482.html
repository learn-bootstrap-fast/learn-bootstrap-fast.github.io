The correct solution is to generate a partner event bus within Amazon EventBridge dedicated to the SaaS provider, and enable event transmission to this partner bus. Partner event buses are specifically designed for external, AWS-integrated SaaS providers, making it the most secure and proper way to accept third-party event data. This setup is necessary because events from SaaS partners are received via partner event sources and require a dedicated event bus for segregation and management.

Option Provision an IAM user specifically for the SaaS partner, granting it permission to publish events directly to the default EventBridge event bus is incorrect because SaaS integrations with EventBridge use event sources, not direct IAM user access for event publishing.

Option Share an IAM role with Amazon EventBridge permissions by providing its ARN to the SaaS provider to link their event source is not the valid approach. Associating an IAM role and sharing its ARN is neither required nor recommended for third-party SaaS connections with EventBridge.

Option Locate the event source identifier supplied by the SaaS partner and allow reception for that ID on the default EventBridge bus is not complete or correct; the proper action is to create a partner event bus corresponding to the external event source. The default bus is not used for SaaS event sources.

Tip: Always refer to AWS documentation for EventBridge SaaS integration, and remember that events from partners are routed to a dedicated event bus for each partner integration.
