The entities that can be allowed to send events to a CloudWatch Event Bus in another AWS account (such as a master/centralized account) are individual AWS accounts, organizations, or 'all' AWS accounts.

The Any AWS account globally (all AWS accounts) option is correct, as AWS allows granting permissions using a wildcard account ('*') principal, meaning all AWS accounts are permitted.

The An external AWS Organization (different from the master’s organization) option is also correct. CloudWatch Event Bus permissions can be granted at the AWS Organization level, including organizations outside of your own (by specifying their Organization ID), enabling all accounts under that organization to forward events.

Specific IAM users from within the same AWS Organization are not valid principals for CloudWatch Event Bus event sources; permissions are not granted at the IAM user level.

A separate AWS account that creates a CloudWatch Event rule in region ap-south-1 to deliver events to the master account is incorrect because the event bus permission is not dependent on the source region, but rather on which account or organization is allowed; region mismatch does not affect principal permissions.

IAM groups as principals is incorrect because CloudWatch Event Bus permissions cannot be assigned to IAM groups.

  • Tip: When sharing event buses, permissions are managed at the AWS account or AWS Organization level, not at the IAM user or group level.
  • Exam Insight: Pay special attention to the distinction between entity types that can be granted permissions for cross-account CloudWatch Event Bus access!
