The most effective way to achieve this is to use a CloudFormation stack for the shared AWS resources and export their outputs. Other stacks can reference these with the Fn::ImportValue function. This method enables you to centrally maintain common resources and let other stacks reliably import just the needed outputs, supporting easier management and modular architecture.

The option Create a CloudFormation stack for the shared resources and have other stacks access them through the Fn::GetAttr function is incorrect because Fn::GetAttr can only reference resources within the same stack or nested stacks, not between independent stacks. The Launch a base stack with shared resources and include it as a nested stack within application stacks using the AWS::CloudFormation::Stack resource approach would tightly couple the stacks, making it harder to manage the resources independently; also, nesting is generally best for parent/child relationships rather than common/shared components. Similarly, Manage the common resources within a CloudFormation stack, then use the AWS Console’s “Import resources into stack” feature to allow other stacks to reuse them is not designed for this use case—‘Import resources into stack’ is for importing existing resources into management under CloudFormation, not for sharing resources across stacks.

Tip: Use the Export and ImportValue capabilities of CloudFormation outputs to share values easily and consistently between multiple stacks, especially for resources that change infrequently.
