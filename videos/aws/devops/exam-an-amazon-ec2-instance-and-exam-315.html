The correct way for an application running on an Amazon EC2 instance to retrieve AWS API credentials when an IAM role is assigned to the instance is to use the AWS SDK. The SDK accesses the EC2 instance's metadata service to automatically obtain temporary credentials tied to the IAM role. Let the AWS SDK automatically retrieve credentials on your behalf from the EC2 metadata service when IAM roles are attached to the instance. This approach eliminates the need for manual key management and reduces the risk of credential leakage.

Why the other options are incorrect:

  • Configure your application to obtain API keys from the instance's environment variables, as assigning an IAM role stores these credentials in environment variables at launch. — This is inaccurate. Assigning an IAM role to an EC2 instance does not store credentials in environment variables by default. The SDK retrieves them from the instance metadata, not from environment variables.
  • Direct your code to fetch credentials by making a GET request to the IAM Service API from within the application. — Applications should never directly call the IAM API to fetch credentials. Credentials are securely provided to the instance via the metadata service.
  • During EC2 instance setup in the AWS Console, select your preferred SDK in a dropdown menu and it will be configured with the appropriate API keys during launch. — There is no such SDK selection dropdown in the EC2 Console, and AWS does not auto-inject SDKs or credentials in this way.

Tip: When using EC2 instance profiles (IAM roles for EC2), always rely on the SDK's built-in logic to retrieve and refresh credentials automatically from the instance's metadata endpoint. This is best practice for both security and operational simplicity.
