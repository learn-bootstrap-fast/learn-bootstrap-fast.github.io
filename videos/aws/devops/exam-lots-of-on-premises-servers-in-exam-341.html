AWS Server Migration Service (SMS) is the optimal choice for this scenario. SMS is designed to migrate on-premises servers—including Windows VMs hosted on Microsoft Hyper-V—to AWS by automating, scheduling, and tracking incremental replications of live server volumes. This service can periodically generate Amazon Machine Images (AMIs) and provides an interface to monitor the entire migration process, fitting all the requirements laid out in the question.

Examining the other options:

  • AWS Migration Hub acts as a central tracking and visualization service for migration progress across multiple AWS tools, but it does not perform migrations or replication itself. It instead aggregates status data from services like AWS SMS, DMS, or Application Migration Service.
  • AWS DataSync is geared toward efficient data synchronization between on-premises storage and AWS (e.g., S3, EFS, FSx), and doesn't support VM replication, AMI creation, or server migration.
  • AWS Database Migration Service is specific to database migrations, facilitating homogeneous or heterogeneous moves (e.g., Oracle to Aurora). It cannot handle full server or application stack migrations or the replication of OS-level VMs.

Tip: When migrating whole servers or VMs, focus on services like SMS or Application Migration Service, not tools that are focused only on tracking, database, or file migrations.
