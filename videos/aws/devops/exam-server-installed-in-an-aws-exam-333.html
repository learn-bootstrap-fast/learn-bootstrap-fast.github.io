Establish a backup and restore process: schedule daily backups of Jenkins configuration files to Amazon S3, and use CloudFormation to quickly redeploy resources if necessary. is the most suitable option in this scenario.

  • Both RTO and RPO are set at 24 hours, which means your organization can tolerate up to 24 hours without the Jenkins server and up to 24 hours of data loss. The backup & restore pattern is the most cost-effective and operationally simple approach when recovery can be reasonably handled within these windows.
  • Automating regular backups of configuration files to S3 ensures that you always have a recent copy ready for restoration. Combining this with CloudFormation allows for automated and consistent re-provisioning of the server infrastructure, keeping recovery simple and within the permitted RTO/RPO.

The other options are less appropriate for these requirements:

  • Implement a Warm Standby solution: launch a smaller-scale EC2 server in another VPC within the same region to act as a standby Jenkins instance. — Warm standby strategies are designed for lower RTO/RPO; typically minutes to an hour. They are more costly because they keep servers running and ready, which isn’t necessary when 24-hour windows are acceptable.
  • Set up a Pilot Light configuration: maintain an AMI image so an EC2 instance can be launched in a different region and kept off to minimize costs, starting it when needed. — While pilot light is used for reduced cost, it is often more complex to implement than basic backup & restore, and is more suited when infrastructure and application state need to be preserved and restored rapidly.
  • Deploy a Hot Standby solution: provision a fully running EC2 server mirroring the Jenkins environment, but pause its workload unless a failover is triggered. — Hot standby (multi-site) solutions are intended for organizations that require minimal downtime and minimal-to-zero data loss (very low RTO/RPO). This is far beyond the requirements here and much more expensive to maintain.

Tip: Always align your disaster recovery solution to your actual RTO/RPO needs. When 24 hours is sufficient, simple daily backups and automated restoration can save both money and complexity.
