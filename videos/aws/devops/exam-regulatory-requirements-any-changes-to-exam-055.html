The best practices for Infrastructure as Code (IaC) emphasize automation, repeatability, and auditable configuration changes. Leverage a CloudFormation template to recreate a production environment in a different AWS region for disaster recovery and Author a JSON document for AWS Systems Manager Run Command to automate EC2 instance health checks and store the script in a Git repository both adhere to these principles. CloudFormation templates make environment creation automated and version-controlled, ensuring all changes are traceable and can be replicated elsewhere. Similarly, placing automation scripts in version control allows for change management, review, and traceability, which meet compliance and documentation demands.

The remaining answers do not align fully with IaC best practices: Utilize AWS CLI from a developer’s local Linux PC is a manual process, prone to human error and lacking traceability; Initiate VPC peering to link two VPCs is a specific network-related setup and, unless automated and managed in code, does not guarantee a trackable change history; and Enable S3 bucket versioning via the AWS Management Console is a console-based configuration that doesn't provide infrastructure automation or inherent documentation. For robust compliance and audit requirements, all infrastructure changes should ideally be managed as code and stored in version control systems such as Git.
