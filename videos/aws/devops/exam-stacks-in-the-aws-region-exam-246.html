The correct answer is: Alter Stack Beta to eliminate the cross-stack import so it no longer imports the output from Stack Alpha.

Here's why:

  • As long as a resource output is being imported by another stack, you cannot remove or modify that export from the exporting stack (Stack Alpha). Therefore, you cannot delete Stack Alpha (Delete Stack Alpha via the AWS Console...), nor can you remove or change the resource output in Stack Alpha (Edit Stack Alpha to delete the output... and Modify Stack Alpha to update the exported security group's name in its output value.) while Stack Beta still references that value.

  • To safely make changes to the export or delete Stack Alpha, you must first update Stack Beta so that it no longer imports the value. This breaks the dependency, freeing Stack Alpha for changes. Thus, updating Stack Beta to remove the cross-stack reference is the only viable action here.

Tips:
  • When using CloudFormation cross-stack references, always remove the imports before making changes or deletions to the exports.
  • If you attempt to delete or modify an exported value that is being imported elsewhere, CloudFormation will block the operation and show a dependency error.

Summary: Remove cross-stack references first from importing stacks before changing or deleting outputs in exporting stacks.
