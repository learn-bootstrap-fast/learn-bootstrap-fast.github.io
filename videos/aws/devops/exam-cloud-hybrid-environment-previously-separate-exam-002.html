To successfully connect your on-premises Ubuntu 16.04 LTS servers to AWS CodeDeploy, several specific requirements must be met:

  • The user account managing the server setup must possess either sudo or root privileges. This is required because the CodeDeploy agent installation and certain operations need administrative rights to make changes to the system files and configurations.
  • The server should be registered with an IAM identity that has the required permissions for CodeDeploy registration. Proper IAM credentials (IAM user or role with CodeDeploy registration permissions) ensure secure communication and allow the server to interact with AWS CodeDeploy as needed.

The incorrect options are as follows:

  • Outbound connectivity to AWS service endpoints via port 80 must be permitted from the on-premises server. This is incorrect because CodeDeploy does not require outbound access over port 80; it generally communicates over port 443 (HTTPS) for secure communication with AWS endpoints.
  • It is necessary to set up either a VPN or AWS Direct Connect between the datacenter and AWS. While these options enhance security and reliability, they are not mandatory prerequisites. Public internet access to AWS endpoints is sufficient if security policies allow.
  • Java 8 installation is required for CodeDeploy agent functionality. This is a common misconception. The CodeDeploy agent is written in Ruby for Linux-based systems (like Ubuntu), so Java is not a necessity for the agent to run correctly.

Tip: Always ensure that the server has network access to AWS CodeDeploy endpoints (generally via HTTPS/port 443), and review the required permissions in the associated IAM entity for trouble-free registration and deployment.
