Change the inbound rule in the security group attached to the EC2 instances, as Network Load Balancers do not support security groups. This is the correct action because unlike Application Load Balancers, Network Load Balancers operate at the connection layer (Layer 4) and do not directly support security groups. Therefore, it's essential to update the security group settings of your EC2 targets to permit the necessary traffic from the NLB on the designated TCP port.

Option Use a template in CloudFormation to connect the same security group to your Network Load Balancer resource is incorrect as NLBs do not support security groups at all—CloudFormation or otherwise.

Option Set the source in the security group's inbound rule to 0.0.0.0/0, otherwise the Network Load Balancer will prevent ingress traffic is misleading; you should always follow least-privilege best practices and only allow traffic from necessary sources. The NLB doesn't restrict ingress traffic, but your instance's security group must permit it from wherever the NLB forwards traffic.

Option Attach a security group directly to a Network Load Balancer listener to allow custom TCP port traffic is invalid, since NLB listeners never have security groups. Security group rules only apply to ENIs (Elastic Network Interfaces), such as those attached to EC2 instances or to ALBs.

Tip: Always remember that only ALBs (and Classic Load Balancers in certain cases) can have security groups. NLBs cannot, so instance-level security groups must be your focus for regulating ingress from NLBs.
