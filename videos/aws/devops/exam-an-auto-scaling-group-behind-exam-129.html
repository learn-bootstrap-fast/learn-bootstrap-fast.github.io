Option 1 and Option 2 are the two solutions that best meet all requirements for durability, log collection during instance termination, and hourly reporting:

  • Install the Amazon CloudWatch Logs Agent on each web server... - CloudWatch Logs is designed to stream server logs in near real time. By installing the agent and using Metric Filters, you can create custom metrics, such as tracking unique visitors. Scheduling a report via a separate EC2 job allows for reliable analytics. Since CloudWatch logs are streamed off-host, data remains available even when EC2 instances terminate. This process is fully managed and efficient for dynamic environments with frequent scale-in/out activity.
  • Configure the web servers to run a routine task that rotates and uploads logs to Amazon S3... - Rotating and copying logs to an S3 bucket upon schedule and during shutdown ensures no data is lost, as S3 is highly durable. Data Pipeline then reliably moves data into Amazon Redshift for fast, scalable analytics and hourly reporting. Both S3 and Redshift are well-established for durability and scalability, making this a robust choice for variable server populations.

Why the others are incorrect:

  • Set up a scheduled task on the servers to rotate and send logs directly to Amazon Glacier... - Amazon Glacier is primarily for cold, archival storage and not meant for frequent or fast access. Processing logs every hour from Glacier would be slow, expensive, and impractical for timely analytics since Glacier retrieval can take several hours. This workflow is not suitable for hourly reporting needs.
  • Install an AWS Data Pipeline-specific Logs Agent on every server as part of the deployment... - There is no AWS Data Pipeline log agent; the service is intended for data orchestration and ETL, not direct log collection from web servers. Moreover, Data Pipeline does not provide a native metric filter mechanism nor direct server-to-Redshift streaming logs, making the option technically infeasible.

Tip: For highly ephemeral infrastructure, push logs to a durable, centralized service (CloudWatch Logs or S3) immediately and at shutdown to prevent data loss on termination. Use managed solutions for analytics and reporting to maximize availability and minimize complexity.
