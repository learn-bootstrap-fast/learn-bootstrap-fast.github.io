The optimal solution requires unlocking Trusted Advisor resource utilization checks, specifically for EC2, as these checks help identify underutilized resources. These advanced checks are only available with the 'Business' or 'Enterprise' support plans. Therefore, upgrading to the 'Business' support plan (option 1) is essential—it is more cost-effective than going straight to Enterprise, and still provides the necessary Trusted Advisor checks.

Additionally, you need to use CloudWatch Events (now called EventBridge) to trigger notifications based on Trusted Advisor activity. By creating a rule with Trusted Advisor as the event source and choosing 'Check Item Refresh Status' (option 2) as the event type, your solution ensures that your Lambda function is invoked whenever there are updates on resource utilization states. This allows you to send custom alerts to your manager.

Why are the other options not suitable?

  • 'Change the AWS support plan to Developer so that all Trusted Advisor features become accessible.' — The Developer support plan only provides a handful of Trusted Advisor checks and does not include the EC2 low utilization check needed for this scenario.
  • 'Upgrade the AWS support plan to Enterprise to enable every cost monitoring feature.' — While the Enterprise plan offers all features, it is unnecessary for this requirement and incurs higher costs compared to the Business plan, which already provides the needed functionality.
  • 'Configure a CloudWatch rule for Trusted Advisor with the event type as All Events.' — Using 'All Events' may result in numerous irrelevant triggers instead of just the utilization checks, leading to unnecessary Lambda executions and noise.

Tip: Always ensure your selected support plan supports the Trusted Advisor checks you require for your automation and monitoring scenarios.
