The recommended practice is to design individual templates that focus on specific functionality, and orchestrate deployment using nested stacks in CloudFormation. This approach enables reusability, modularizes infrastructure, simplifies template management, and permits efficient updates—all while maintaining agility and supporting multiple environments such as dev, test, and prod.

The option Utilize multiple templates within a single CloudFormation stack is not valid because a single stack is based on a single template; CloudFormation does not allow multiple templates per stack.

Employ CloudFormation custom resources solely for managing stack interdependencies is incorrect because custom resources are intended for enhancing template functionality with external logic and not specifically for stack relationship management, which is more cleanly managed with nested stacks.

Aggregate all resources into one comprehensive template to streamline automation and enable version control quickly leads to complex and unmanageable templates, hindering agile practices and complicating updates, especially when scaling for multiple environments.

Tip: Structuring infrastructure as modular, reusable nested stacks makes it easier to maintain, version, and automate across various environments.
