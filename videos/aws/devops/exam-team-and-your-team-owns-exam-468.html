To filter and match only events originating from AWS account B, you can approach the solution in two correct ways:

  • Selecting the pre-defined pattern by AWS account is the quickest and most straightforward, as EventBridge lets you specify the source account directly using a dropdown. This method requires minimal configuration and reduces the chance of misconfiguration.
  • Defining a custom event pattern containing the account field (for example: { \"account\": [ \"222222222222\" ] }) manually specifies that only events from account B’s AWS account ID will be matched—which is useful if you require more granular or additional event attribute matching or can't use the pre-defined selector.

The other options are not optimal:

  • Enable the rule on the selected event bus. is necessary but does not filter events by source account, so alone it does not solve the requirement.
  • Select a custom pattern, then choose the custom event bus being used by account B. is misleading because it is account B sending the events to the default event bus in account A (unless a custom bus is set up), and filtering should be done via event pattern.
  • Configure the rule to apply to all events and set a Lambda function as the destination, filtering events for account B inside the Lambda function code. is operationally inefficient, as it processes all incoming events instead of filtering at the rule level. This could increase cost, latency, and reduces clarity in event handling.

Tip: Always apply specific filters in the EventBridge rule itself whenever possible. This ensures only relevant events trigger downstream actions and reduces complexity and cost.
