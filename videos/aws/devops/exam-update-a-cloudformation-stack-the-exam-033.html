The correct way to safely preview upcoming CloudFormation stack changes is to use the create-change-set command before updating the stack.

Let's break down each option:

  • Use the CloudFormation CLI's create-change-set command as a new step to produce a change set showing all proposed updates. The changes can then be reviewed before allowing Jenkins to proceed.
    This is the recommended method. The create-change-set command lets you generate and review a summary of the specific resource modifications (additions, deletions, replacements, updates) before actually applying them. This process allows the team to catch any unintended recreations or destructive changes and is precisely designed for this workflow.
  • Add a pipeline stage that runs the AWS CLI update-stack command with the --dry-run option enabled, collecting the resulting JSON for manual review.
    This is incorrect because AWS CLI's update-stack does not support a --dry-run flag. The --dry-run option is not available nor capable of previewing stack changes in CloudFormation updates.
  • Have Jenkins upload the revised CloudFormation template via the CLI to trigger drift detection, checking for any resource or configuration drifts before allowing a stack update.
    This is not appropriate. While drift detection finds differences between your actual resources and your template, it does not let you preview what new changes an updated template will apply to your stack. It is used for compliance validation rather than change set previews.
  • Integrate Terraform into the pipeline, utilizing terraform plan to preview stack changes and terraform apply to submit them, since you cannot preview CloudFormation stack changes otherwise.
    This doesn't answer the question, since you are still using CloudFormation and not Terraform. There is no need to migrate or mix tools, and CloudFormation has the required native preview mechanism with change sets.

Tip: Always use change sets in automated pipelines for safe CloudFormation deployments, especially in production environments. This helps prevent accidental disruption and provides an audit trail for approval processes.
