The correct answers are:

  • The post_build phase is the appropriate place to perform the Docker push to Amazon ECR. In CodeBuild, it's standard practice to structure your buildspec.yml to build and tag the Docker image during the build phase, and then push it to Amazon ECR during post_build. This ensures the image is only pushed if the build succeeds.
  • The aws ecr get-login-password command simply gives a token, but you also need to use it to authenticate Docker to ECR. Running aws ecr get-login-password by itself will only retrieve the authentication token. To log Docker in to Amazon ECR, you must use that token in the Docker login command.
  • In the post_build phase, before pushing the Docker image, you must execute aws ecr get-login-password to log in. Before issuing docker push in the post_build phase, you have to authenticate Docker against ECR by using the aws ecr get-login-password in a Docker login command. Failing to do so will result in authentication errors when pushing your image.

‘No authentication is needed if the IAM role grants ECR read-only permissions; CodeBuild automatically handles ECR access’ is incorrect because while the IAM role needs the proper permissions, Docker still requires explicit login—CodeBuild does not log Docker in to ECR automatically for you. ‘You should place the docker push command in the build stage, since post_build is only for cleanup activities’ is also incorrect—the build stage is intended for compiling, testing, and building artifacts. The post_build phase is designed for publishing outputs, such as pushing images.

Tip: Always ensure your buildspec.yml has the necessary authentication and correct phase for pushing artifacts. Remember to use the output of aws ecr get-login-password with Docker login before any ECR push command in each build or deployment session.
