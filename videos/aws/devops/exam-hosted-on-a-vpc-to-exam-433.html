The correct approaches are \"The application verifies users with LDAP and obtains the name of an IAM role mapped to the user. By calling the IAM Security Token Service to assume the IAM role, it retrieves temporary credentials to access AWS resources.\" and \"Set up an identity broker that first authenticates users against LDAP, then requests temporary federated credentials from the IAM Security Token Service. The application gets those federated credentials through the identity broker to interact with AWS services.\"

Both methods enable proper authentication using the on-premises LDAP and leverage AWS IAM Security Token Service (STS) to obtain temporary credentials, promoting secure, scalable, and standards-aligned access.

  • Option 1 is correct because after authenticating against LDAP, the application retrieves the corresponding IAM role for the user and uses STS to generate temporary credentials—following best practices for identity federation and access control.
  • Option 3 is also correct as using a dedicated identity broker to authenticate against LDAP and then obtain federated credentials with STS is a common enterprise integration pattern and recommended by AWS.
  • \"Build an identity broker service which authenticates users with the IAM Security Token Service, enabling the broker to assume an IAM role and obtain temporary AWS credentials. The application obtains those temporary credentials from the broker.\" (Option 2) is incorrect because STS itself cannot perform user authentication; it only issues credentials to trusted entities after authentication—thus, there's no direct authentication against STS.
  • \"Have the application authenticate each user directly using LDAP credentials when calling the AWS Identity and Access Management (IAM) Security service, and use any resulting IAM temporary credentials for AWS resource access.\" (Option 4) is invalid as IAM does not support LDAP credentials for direct authentication; a federation mechanism is required for LDAP to interact with AWS IAM.

Tip: For hybrid cloud authentication, always remember that AWS IAM is federated when integrating with on-premises directories—direct login with LDAP credentials is not possible.
