The correct choice is CodeStar assigns specific IAM policies to each team member role automatically. Users simply need to ensure that the correct roles (Owner, Viewer, Contributor, etc.) are chosen for each team member in the project. This means AWS CodeStar streamlines permission management by associating predefined IAM managed policies to each role, so administrators only need to assign proper roles to their collaborators without manual policy creation.

The other options are incorrect for the following reasons:

You should first define IAM policies suited for individual team members, then manually assign these policies to each IAM user involved in the project. — This approach is not required for CodeStar since CodeStar roles come with built-in policies.

It's necessary to create IAM service roles with relevant permissions, and then link these service roles with each team member in CodeStar according to their required access. — IAM service roles are intended for granting AWS services permissions to act on your behalf, not for assigning to people.

Permissions must be configured by setting team member roles directly in the CodeStar console, which allows assigning granular read or write access to stages such as build and deployment. — While you do assign roles in the console, AWS does not allow for arbitrary granular permission editing at specific stages; instead, permissions are based on predefined CodeStar roles.

Tip: For projects managed by AWS CodeStar, focus on choosing the correct role (Owner, Contributor, Viewer, etc.) for each member, rather than micromanaging IAM permissions.
