The right way to change the Lambda resource name is to update the template.yml file in your CodeCommit repository. This file represents the AWS CloudFormation stack, which defines and provisions all required resources including the Lambda function. After modifying the name in template.yml, committing and pushing your change will let the pipeline (triggered by CodeBuild and CodeStar) redeploy the Lambda resource with the new name.

Option \"Since CodeStar created the Lambda with a preset name, you need to visit the Lambda console and manually re-upload your function using the new name.\" is incorrect because best practice is to manage all infrastructure through the same code base; manual changes in the Lambda console can drift from your source of truth and break automation.

Option \"As the Node.js project sample template is available only in read-only demo mode, changing the Lambda name is not permitted.\" is inaccurate; once the template is provisioned in your own repository, it is fully editable.

Option \"The correct procedure is to check out the code from CodeCommit and change the buildspec.yml file through a commit, which instructs CodeBuild to redeploy the Lambda function using your new chosen name.\" is also incorrect. The buildspec.yml file manages build-related steps, not infrastructure resource names, which are controlled by the CloudFormation template (template.yml).

Tip: Always manage resource properties such as names within the CloudFormation template in your pipeline, not through post-deployment manual edits or buildspec changes. This ensures consistency and repeatability in your deployments.
