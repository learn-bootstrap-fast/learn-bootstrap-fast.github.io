The correct IAM policy is { \"Version\": \"2012-10-17\", \"Statement\": [{ \"Effect\":\"Allow\", \"Action\":[ \"ssm:SendCommand\" ], \"Resource\":\"*\", \"Condition\":{ \"StringLike\":{ \"ssm:resourceTag/department\":[ \"dev1\", \"dev2\" ] }} } ] }. This policy specifically allows the ssm:SendCommand action, which is the action required to use the Run Command feature, but only if the EC2 instance has the department tag set to either dev1 or dev2. The use of StringLike with an array properly matches either tag value.

Let's review the other options:

  • { \"Version\": \"2012-10-17\", \"Statement\": [{ \"Effect\": \"Allow\", \"Action\": [\"*\"], \"Resource\": \"*\", \"Condition\": { \"StringLike\": { \"ssm:resourceTag/department\":[ \"dev1\" ], \"ssm:resourceTag/department\":[ \"dev2\" ] }} }] }: This option incorrectly specifies the Action as [\"*\"], which is too permissive and not secure. Additionally, the Condition field lists ssm:resourceTag/department twice, which is invalid JSON and will not work as intended.
  • { \"Version\": \"2012-10-17\", \"Statement\": [{ \"Effect\": \"Allow\", \"Action\": [ \"ssm:SendCommand\" ], \"Resource\":\"*\", \"Condition\":{ \"StringNotEquals\":{ \"ssm:resourceTag/department\":[ \"dev1\", \"dev2\" ] }} }] }: Here, StringNotEquals would do the opposite, denying access to resources with department=dev1 or dev2. This does not meet the requirement and is the inverse of the intended functionality.
  • { \"Version\": \"2012-10-17\", \"Statement\": [{ \"Effect\":\"Allow\", \"Action\":[ \"ssm:RunCommand\" ], \"Resource\":\"*\", \"Condition\":{ \"StringLike\":{ \"ssm:department\":[ \"dev1\" ], \"ssm:department\":[ \"dev2\" ] } } } ] }: This option uses the incorrect action name ssm:RunCommand (it should be ssm:SendCommand), and also refers to the tag key as ssm:department rather than ssm:resourceTag/department. Both errors mean this policy would not properly control access via tags as required.

Tip: Always use the correct IAM actions and ensure that conditions referencing tags use the format ssm:resourceTag/[tagKey] for resource-level permissions. Group multiple allowed values within a single array as shown.
