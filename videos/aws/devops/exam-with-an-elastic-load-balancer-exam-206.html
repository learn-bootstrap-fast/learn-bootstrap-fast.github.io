The correct answer is The new instances will not automatically be registered with the ELB. When you suspend the AddToLoadBalancer process, any new EC2 instances created by Auto Scaling are launched, but are not registered with the ELB while the suspension is in effect. When you resume the process, you must manually register these instances with the ELB if you want them to receive traffic, unless you terminate and relaunch them, allowing Auto Scaling to automatically register them.

'The Auto Scaling group does not launch any instances while suspended.' is incorrect since only the registration process is paused, not the instance lifecycle. 'Instances are added to the ELB as soon as you resume the AddToLoadBalancer process; no manual actions needed.' is wrong because Auto Scaling will not attempt to register previously launched instances with the ELB unless you do so manually. 'Manual intervention is required to attach the instances to the ELB after resuming the process.' is misleading. Instance registration must be done manually, but this option fails to clarify that automatic registration does not occur upon resuming. 'Suspending the AddToLoadBalancer process is not an available feature.' is incorrect as AWS supports suspension of specific Auto Scaling processes like AddToLoadBalancer.
