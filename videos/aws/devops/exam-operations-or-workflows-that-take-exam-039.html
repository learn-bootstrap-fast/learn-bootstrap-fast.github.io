The correct answer is Handles the configuration of an Amazon SQS queue and supervises a background worker process on each deployed instance.

Elastic Beanstalk provides a special Worker Environment tier for handling long-running or background processing tasks. This environment automatically sets up an Amazon SQS queue, where tasks can be placed by other components (like your web application). Each instance runs a daemon process that fetches messages from the SQS queue and executes the job. This pattern is ideal for offloading time-consuming workflows as it decouples them from the main web server, allowing efficient scaling and fault tolerance.

Why the other options are incorrect:

  • Coordinates Lambda functions and executes a background daemon on every instance. - Elastic Beanstalk does not natively manage Lambda functions in the way described nor does it combine this with daemon processes on EC2 instances.
  • Sets up an Amazon SNS Topic and deploys a continuously running daemon on each instance. - SNS is a pub/sub service not purpose-built for background job queues. Beanstalk worker environments are designed specifically to integrate with SQS rather than SNS.
  • Manages Elastic Load Balancer settings and executes a daemon service on all instances. - While ELB can distribute HTTP traffic, it is unrelated to offloading background tasks with Beanstalk Worker Environments.

Tip: Remember, for background processing with Elastic Beanstalk, think of SQS and Worker Environments!
