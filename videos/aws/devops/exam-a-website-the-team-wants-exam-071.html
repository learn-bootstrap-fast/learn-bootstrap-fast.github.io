Lambda@Edge is the most suitable choice for enabling A/B testing at the CDN layer without changing the browser’s URL or adding custom code to the front or back end. Lambda@Edge allows you to run code within AWS locations worldwide that intercepts requests and responses handled by CloudFront. This enables custom logic (such as A/B test version selection) to be executed based on cookies, headers, or other request attributes before reaching your web servers or origin.

\"Weighted routing policy in Route 53\" is incorrect because while Route 53 can distribute DNS queries to different endpoints, it operates at the DNS layer and can result in cache and redirect behaviors that change the visible URL or are inconsistent for existing users. This is not suitable for A/B tests that must preserve the original browser URL and session consistency.

\"Using AWS Lambda with API Gateway\" does not operate at the CDN level. This approach would require you to put additional logic in your application’s HTTP endpoints (either front-end or back-end), which the scenario specifically wants to avoid.

\"Global Accelerator with CloudFront\" is designed for routing and improving global network latency but does not provide the request transformation or customized logic necessary for fine-grained A/B testing at the HTTP request level within the CDN layer.

Tip: Always leverage Lambda@Edge with CloudFront for advanced content-based or request-based actions at the CDN edge, including personalizations, redirects, or variations for A/B testing, when you do not want to modify your application's codebase.
