This scenario illustrates both a Blue/Green deployment and a Red/Black deployment. Blue/Green deployment is a pattern where two identical environments are used; one runs the live version ('blue') while the new version is rolled out onto the idle environment ('green'). After testing, traffic is switched to the new environment. The same approach is often called Red/Black deployment (the terms are interchangeable, though Blue/Green is more common in AWS).

The answer is not A/B testing as that approach involves diverting traffic between multiple application versions simultaneously to gather data or run experiments, which is not the case here. Rolling deployment refers to gradually updating instances within the same environment without using separate groups—here, the deployment is performed completely on the secondary ASG. Canary deployment involves releasing a new version to a small subset of users before a complete cutover, rather than switching all traffic at once.

Tips: In the AWS context, Blue/Green and Red/Black both describe swapping between entire environments with zero overlap in user traffic; it guarantees easy rollback and minimal risk.
