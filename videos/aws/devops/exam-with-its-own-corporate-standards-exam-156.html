The best solution is to use AWS Config to monitor changes to Service Catalog product instances and create custom rules for automatic remediation, with AWS Systems Manager Parameter Store to track and enforce instance count limits. AWS Config’s main purpose is to record configuration changes and, with custom rules, it can trigger remediation to bring resources back into compliance automatically. Parameter Store is effective for storing and tracking simple values, like a product instance count, helping automate enforcement of resource quotas and budgets.

The following explains why the other options aren't suitable:

  • Set up AWS Control Tower...use AWS Systems Manager Parameter Store to log and enforce the maximum permissible number...: While Control Tower provides governance at an account and OU level, it does not natively monitor Service Catalog product-level changes or enforce quotas. Parameter Store can store values, but the Control Tower part is incorrect for this use case.
  • Deploy AWS Control Tower to both monitor and record changes...and also use it to enforce the maximum allowed number...: Control Tower does not offer configuration change monitoring or quota enforcement for Service Catalog products at the individual resource level.
  • Leverage AWS Config to oversee...while relying on AWS Control Tower to manage and restrict the maximum count...: Although AWS Config is correctly being used for monitoring and triggering actions, Control Tower does not manage product-specific instance limits.

Tip: When you need detailed compliance, auditing, and automation in response to configuration drift in AWS Service Catalog, prefer AWS Config with custom rules for control, and use Systems Manager Parameter Store to centrally track simple configuration values such as quotas.
