The IAM access advisor feature enables you to review service-last-accessed information at the entity level, such as users, roles, and groups. This is particularly useful for determining which AWS services have or have not been utilized recently. For organizational units, using the IAM access advisor provides direct visibility and helps identify services that have been unused for a specified period, allowing you to set precise CloudWatch Events rules.

Looking at the incorrect choices:

  • Use the AWS Organization console to examine each OU and check the last service access details. — The AWS Organizations console does not provide service-last-accessed data directly at the OU level.
  • Query AWS Config via CLI to retrieve service-last-accessed information for every organizational unit. — AWS Config tracks resource configuration changes, not service-last-accessed details. It does not natively track when an OU last used specific services.
  • Create a resource group in the AWS Resource Groups service containing the services of interest, then check last access information from that group. — AWS Resource Groups do not provide service-last-accessed analytics or reporting.

Tip: When you need access history information, IAM access advisor is designed for this use case. Be sure to scope your review to roles, users or groups, as OUs aggregate these entities. Knowing this distinction will help you leverage AWS tools more effectively for auditing and security automation.
