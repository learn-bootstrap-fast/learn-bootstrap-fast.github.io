The correct option is Enable CMEK on the Cloud SQL instance and keep the keys in a Cloud KMS key ring that the security team manages.

With CMEK you choose a Cloud KMS key that can reside in a dedicated key ring within a restricted project controlled by the security team. Cloud SQL uses that key to encrypt data at rest and you grant only the necessary KMS roles to the Cloud SQL service account so the security team retains ownership and access control. You configure key creation and a 120 day rotation schedule on the Cloud KMS key and the instance automatically uses new key versions as they are rotated which satisfies the governance requirements.

Configure Cloud SQL to use customer supplied encryption keys and store the keys in Cloud KMS is incorrect because Cloud SQL does not support customer supplied encryption keys and it supports customer managed encryption keys with Cloud KMS instead.

Configure Cloud SQL to use customer managed encryption keys and keep the keys in a third party key manager is incorrect because Cloud SQL CMEK requires keys stored in Cloud KMS and Cloud EKM third party key managers are not supported for Cloud SQL.
