The correct option is Use Cloud SQL serverless export to write the data to Cloud Storage.

This feature runs the export as a managed job outside your database instance which keeps CPU and I O impact off the primary. It writes directly to Cloud Storage and can be automated with simple scheduling so it meets the goals of minimal operational effort and minimal impact. It is well suited for large datasets where you need recurring backups without affecting availability.

Run the pg_dump utility on the primary instance and export directly to a Cloud Storage bucket is not appropriate because pg_dump would consume resources on the primary and can significantly affect performance when exporting multiple terabytes. It also requires you to manage the compute environment and data movement which increases operational effort.

Create a read replica and execute pg_dump against the replica to export the database reduces load on the primary but still requires you to provision and operate a replica and to manage long running dumps. Large exports can cause replica lag and the process remains operationally heavy compared to a managed export job.

Use Cloud SQL automated backups and copy them to Cloud Storage using Storage Transfer Service is not feasible because automated backups are managed by Cloud SQL and are not exposed as files that you can copy with Storage Transfer Service. You cannot directly move those backups into your buckets.
