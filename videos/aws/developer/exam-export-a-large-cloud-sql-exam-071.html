The correct option is Run a serverless export from Cloud SQL.

Run a serverless export from Cloud SQL uses Google managed resources to perform the export and writes the output to Cloud Storage. This keeps the heavy work off the primary instance so CPU and memory pressure on the production database remain low. It is designed for large datasets and long running jobs and it is the best fit when you need to archive data without affecting live traffic.

Database Migration Service is built for moving data into Cloud SQL and ongoing replication during migrations. It does not produce an on demand archival export to Cloud Storage and it is not intended for one time compliance backups.

Run pg_dump from a Compute Engine VM through the Cloud SQL Auth Proxy would pull data through the proxy by running queries on the primary instance. That approach consumes instance CPU and I O and can prolong locks or contention which risks degrading performance on a busy production system.

Datastream focuses on change data capture for continuous replication into destinations such as BigQuery or Cloud Storage. It is not a simple one time full export of all databases for archival purposes and it does not minimize load on the primary instance the way a managed serverless export does.
