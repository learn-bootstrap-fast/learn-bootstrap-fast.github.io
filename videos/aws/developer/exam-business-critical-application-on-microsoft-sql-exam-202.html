The correct option is Compute Engine because it lets you lift and shift your three Windows servers that run the SQL Server database engine together with SSAS, SSRS, and SSIS while preserving the current architecture with minimal change.

With virtual machines on Google Cloud you can provision Windows Server instances that mirror your existing roles and you can install or use prebuilt images for SQL Server. You can keep the same separation of duties across three servers and you can join them to Active Directory and maintain existing configuration and scheduling. You can choose storage and networking layouts similar to on premises and you can implement high availability with technologies such as Always On availability groups or failover clustering when needed.

BigQuery is a serverless data warehouse rather than a relational database engine that you administer at the OS level. It does not host SQL Server nor SSAS, SSRS, or SSIS and moving to it would require redesigning data models, ETL, and reports which is not a minimal change.

Cloud SQL for SQL Server manages only the SQL Server database engine and does not allow installing or running SSIS, SSRS, or SSAS. It also does not provide Windows host access, which prevents preserving the current multi server architecture.

Google Kubernetes Engine would require containerizing SQL Server and the associated services and running stateful Windows workloads in containers, which is complex and represents a significant redesign rather than a straightforward preservation of the existing architecture.
