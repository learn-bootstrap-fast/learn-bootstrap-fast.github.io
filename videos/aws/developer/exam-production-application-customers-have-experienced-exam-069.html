The correct options are Configure the Cloud SQL instance for high availability and Set a preferred maintenance window.

Configure the Cloud SQL instance for high availability ensures a primary and standby instance in different zones with automatic failover during maintenance or zonal issues. This minimizes write downtime and keeps the checkout API available because failover is quick and managed by the service.

Set a preferred maintenance window allows you to schedule maintenance during low traffic periods. This does not remove maintenance but it places it when impact is lowest and when combined with automatic failover the customer effect is greatly reduced.

Opt in to maintenance notifications only informs you that maintenance is coming. It does not change when maintenance occurs and it does not preserve availability during the event.

Disable automated backups reduces your recovery options and does not lessen maintenance impact. Backups are essential for recovery and their removal does not prevent restarts or shorten maintenance operations.

Add a read replica and plan to promote it during maintenance is not a good strategy for availability. Read replicas are asynchronous and promotion is manual and disruptive which can cause write downtime and potential data loss. This does not provide seamless failover during maintenance.
