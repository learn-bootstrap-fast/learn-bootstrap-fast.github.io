The correct answer is Create a Cloud Function that starts and stops the Cloud SQL instances and schedule it with Cloud Scheduler to match the team's working hours.

This solution automatically pauses compute charges outside business hours while keeping storage available and it removes the need to manage servers or cron processes. Cloud Scheduler provides reliable time based triggers and the function can call the Cloud SQL Admin API to stop or start instances with least privilege IAM. This keeps administration simple and scales easily as engineers add or remove sandbox databases.

Run a small Compute Engine VM with a cron job that uses gcloud to start and stop the Cloud SQL instances at the beginning and end of the workday is not ideal because you pay for a VM that exists only to run a schedule and you add patching and reliability overhead. A serverless schedule is simpler and more cost effective.

Enable high availability on the Cloud SQL instances and set the maintenance window to evenings outside working hours does not reduce daily compute cost and actually increases spend due to HA replicas. Maintenance windows control planned updates and they do not stop instances.

Add a read replica for every sandbox Cloud SQL instance and set a maintenance window outside business hours increases cost and does not address turning off instances when they are not needed. Replicas improve read scalability and availability rather than cost savings.
