The correct actions are Migrate the database to a Cloud Spanner multi region configuration and Schedule automated backups of the Spanner database to Cloud Storage.

A multi region Spanner deployment provides synchronous replication across regions with automatic failover, which delivers a very small recovery point objective and a rapid recovery time objective for a regional outage. Writes commit only after achieving quorum across replicas, so data loss is minimized, and failover is handled by the service which keeps recovery fast and predictable.

Regularly scheduled backups add a second layer of protection by enabling recovery from data corruption or accidental deletion. Keeping backups in an independent storage location and automating their creation ensures you can restore to a known good state while the multi region design handles live regional outages with minimal disruption.

Maintain a cold standby Spanner instance in a separate region is insufficient because Spanner does not support ad hoc cross instance replication, and a cold standby would require manual promotion and data synchronization which increases both RPO and RTO.

Consolidate the deployment into a single region to simplify operations reduces resilience and directly contradicts the requirement to withstand a regional outage while maintaining very small RPO and rapid RTO.

Enable automatic database tuning features may improve performance or efficiency, yet it does not provide the cross regional redundancy or restore capabilities needed to meet the disaster recovery objectives.
