The correct option is Enable point in time recovery on the Cloud SQL instance. This feature allows you to restore the database to an exact moment in the recent past which directly addresses protection against accidental deletes or bad writes.

With Enable point in time recovery on the Cloud SQL instance, Cloud SQL retains the necessary logs alongside backups so you can choose a precise timestamp within the retention window. This gives you a much finer recovery point than periodic backups or exports and is specifically designed to recover from logical errors such as unintended updates or deletes.

Configure read replicas for the instance is incorrect because replicas are intended for read scaling and can assist with availability, yet they replicate the same deletes and bad writes. They do not provide a way to roll the data back to a previous state.

Schedule daily exports to Cloud Storage using Cloud SQL export is incorrect because exports only let you restore to the time of the last export. That does not satisfy the requirement to recover to an exact moment and it can leave a large gap in data.

Enable automated backups for the instance is incorrect on its own because backups let you restore to a backup snapshot time rather than any chosen point. Without point in time recovery you cannot target an exact moment between backups.
