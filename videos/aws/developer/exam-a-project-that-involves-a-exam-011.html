The correct option is Create region-specific maintenance windows that align with each region's off-peak hours and send notifications only to database administrators.

Cloud Spanner supports maintenance windows so you can steer disruptive updates into predictable times. In a multi region deployment where demand follows local time, aligning each region's window with that region's off peak hours minimizes impact on users while Google performs rolling maintenance to preserve availability. Notifying the database administrators ensures the responsible team is prepared to coordinate and monitor the changes.

Configure one global maintenance window during the lowest worldwide activity and send notifications only to database administrators is incorrect because a single global window cannot match local off peak times across all geographies, which would cause some regions to receive maintenance during their busy periods.

Create region-specific maintenance windows that align with each region's busiest hours and notify only database administrators is incorrect because scheduling during the busiest hours maximizes impact rather than minimizing it.

Use Cloud Scheduler with a Cloud Function to postpone Cloud Spanner maintenance during busy periods and notify service owners is incorrect because Cloud Spanner maintenance is managed by Google and cannot be postponed or overridden with custom jobs. You must use the built in maintenance window controls to influence timing.
