The correct option is Enable point in time recovery for the Cloud SQL instance.

This capability retains the transaction logs and lets you restore the database to a precise timestamp within the configured retention window. That meets the need to roll back to a moment just before the accidental change in the past 36 hours and it limits data loss to only a few minutes. You must configure the retention window to cover at least 36 hours to satisfy this requirement.

Create a read replica in another region addresses read scaling and disaster recovery rather than targeted rollback. It mirrors changes from the primary so it cannot rewind to a specific moment and promoting a replica would not let you restore to just before the change.

Schedule automated backups for the instance creates restore points at backup times only. You cannot restore to an arbitrary moment between backups so you could lose many hours of data without the continuous logging that enables near minute level recovery.

Configure high availability with a standby instance improves uptime by failing over during zonal issues or maintenance. It does not enable rolling back unwanted changes because the standby has the same data state as the primary.
