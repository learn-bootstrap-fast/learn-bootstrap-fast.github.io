The correct option is Set the VPC dynamic routing mode to global.

Dedicated Interconnect relies on Cloud Router to exchange routes with on-premises. With the default regional dynamic routing mode, the Cloud Router in us-central1 only advertises subnets from that region and only imports learned routes for that region. Switching the VPC to global dynamic routing lets the Cloud Router advertise all VPC subnets from every region to on-premises and makes the learned routes available across the VPC. As a result, on-premises clients can reach the europe-west1 database over its private IP through the existing Interconnect.

Create a Cloud NAT gateway for the subnet that hosts the database VM is incorrect because Cloud NAT provides outbound internet access for private instances and it does not enable inbound connectivity from on-premises over Interconnect.

Establish an HA VPN tunnel between us-central1 and europe-west1 within the same VPC is incorrect because a single VPC is already global and does not require VPN between its regions. HA VPN is for connecting different networks and it would not change what routes are advertised to on-premises over the Interconnect.

Configure the Cloud Router with custom route advertisements that include the europe-west1 subnet is incorrect because custom advertisements do not change the regional scope of route advertisement. When the VPC is in regional mode, a Cloud Router in us-central1 cannot advertise subnets from europe-west1. You must use global dynamic routing to advertise those prefixes.
