The correct option is Create authorized views in a separate dataset that filter by carrier identifier and grant carriers access only to the views.

Authorized views let you expose queryable results without giving users any permission on the underlying tables or on the production dataset. You place the views in a separate dataset and grant carriers access only to those views, while you authorize the views to read from the base tables. This meets the requirement because carriers can run SQL against approved objects and they never receive privileges on the base tables or the production dataset.

Share the source dataset with all carriers and define BigQuery row access policies for each carrier is incorrect because sharing the dataset grants permissions on the production dataset and potentially the base tables, which violates the stated constraint. Row access policies control which rows are visible but they do not remove the need to grant table or dataset permissions to the users.

Export each carrier's rows to Cloud Storage and let carriers retrieve their data files is incorrect because the users need to run SQL against approved objects. Files in Cloud Storage are not queryable in BigQuery without additional setup and this approach adds operational overhead and does not satisfy the requirement to run SQL directly.

Apply Data Catalog policy tags to sensitive columns and give carriers read access to the dataset is incorrect because policy tags provide column level controls and do not restrict access by row for each carrier. Granting dataset read access would also give permissions on the production dataset, which the requirement forbids.
