The correct option is Cloud Spanner with a multi-region instance and interleaved parent-child tables.

A multi region Cloud Spanner instance replicates data across at least three regions with synchronous writes and automatic failover, which delivers very high availability and disaster recovery without manual intervention. It provides horizontal scalability for both reads and writes and guarantees strong external consistency while supporting complex relational SQL and fully transactional workloads. This directly matches the needs of a core ledger that must stay consistent and fast across regions.

Using interleaved parent child tables in Cloud Spanner colocates related rows so most queries and transactions stay within the same split or shard. This keeps read and write latency low and reduces coordination overhead for hierarchical ledger entities such as accounts, balances, and postings.
