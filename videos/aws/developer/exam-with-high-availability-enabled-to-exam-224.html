The correct configuration is Enable automatic storage increase on the Cloud SQL instance.

This setting monitors free space and grows the underlying storage automatically before the instance runs out. The resize is online and does not cause downtime or require operator action. It continues to expand up to the per instance storage maximum supported by Cloud SQL and works with high availability so the primary and standby remain healthy through expansions.

Cloud Spanner is a different managed database service and adopting it would require migration rather than configuring the existing Cloud SQL instance. The question asks for a configuration to apply to the current instance so this is not appropriate.

Create read replicas for the Cloud SQL instance helps scale read traffic and can improve availability for reads but replicas do not increase the primary instance storage capacity and they do not address automatic disk growth.

Schedule a weekly job with Cloud Scheduler and Cloud Functions to grow the disk is unnecessary because Cloud SQL already provides native automatic storage increases. A periodic job is reactive and may miss sudden growth and it adds operational complexity without improving availability.
