The correct option is Enable Cloud SQL high availability and place the standby in a different zone to allow automatic failover during maintenance.

This configuration creates a regional instance with a primary and a synchronous standby in another zone, and during planned maintenance the system can promote the standby automatically. This prevents the application from experiencing an outage because connections fail over to the healthy instance while maintenance proceeds on the other. It is the most direct and immediate step to avoid downtime from future maintenance events without requiring an application redesign.

You can also set a maintenance window within Cloud SQL to align maintenance with low traffic periods, although that only influences timing. The high availability setup is what eliminates downtime by allowing failover during maintenance.

Migrate the database to Cloud Spanner to avoid downtime from maintenance is not an immediate step and it requires significant schema and application changes, and it is not a drop in replacement for Cloud SQL engines. This would not address the urgent need to prevent the next maintenance outage.
