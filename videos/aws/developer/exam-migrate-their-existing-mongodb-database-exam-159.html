The correct pairing is MongoDB Atlas Live Migration and MongoDB Atlas on Google Cloud.

MongoDB Atlas on Google Cloud is a fully managed service that preserves MongoDB compatibility so applications do not require refactoring. Live Migration performs an initial sync and then continuously replicates changes from the source which allows you to schedule a brief cutover that can be kept under 15 minutes. Because MongoDB Atlas uses the same flexible document model as the source it can handle ongoing schema changes during the migration. Live Migration supports verification steps to check data consistency and since the source cluster remains intact you can quickly roll back by redirecting traffic if issues arise after cutover.

Cloud Dataflow with MongoDB connector and Firestore in Native mode is not suitable because Firestore is a different database with a different API and query model and it does not provide a managed path for ongoing change replication with near zero downtime or an easy rollback mechanism.

Database Migration Service and Cloud SQL for PostgreSQL with JSONB would require application changes because Cloud SQL for PostgreSQL does not support the MongoDB wire protocol and Google Cloud Database Migration Service does not migrate from MongoDB to Cloud SQL. This pairing does not meet the low downtime or validation and rollback needs.

Database Migration Service and Cloud Bigtable is not appropriate because Bigtable is a wide column store rather than a document database and Database Migration Service does not migrate to Bigtable. This option would not preserve MongoDB compatibility or provide the requested migration capabilities.
