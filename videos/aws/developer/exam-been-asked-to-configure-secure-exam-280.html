The correct option is Run the Cloud SQL Auth Proxy on the VM and connect using the instance connection name. This meets the requirements for no public exposure, strong encryption, IAM based authorization, and seamless failover.

The Cloud SQL Auth Proxy uses IAM credentials from the VM service account so you can grant the Cloud SQL Client role and authorize connections without static database passwords. It establishes a secure TLS connection with automatic certificate verification which provides strong encryption without the burden of managing client certificates yourself.

The Cloud SQL Auth Proxy connects using the instance connection name and automatically discovers and reconnects to the current primary during failover. This provides seamless high availability without manual IP or DNS changes. You can pair the proxy with a private IP configuration so there is no public endpoint while still benefiting from IAM enforcement and encrypted transport.

Configure a Cloud VPN tunnel between the VM VPC and the Cloud SQL service is not viable because Cloud SQL is a managed service that is not reachable over your VPN and this does not address IAM based authorization or connection failover behavior.

Expose a public IP on the Cloud SQL instance and allow only the VM external address using authorized networks and firewall rules violates the requirement to avoid public exposure and relies on IP allowlisting rather than IAM authorization. While SSL could be added, it increases management overhead and does not satisfy the IAM requirement.
