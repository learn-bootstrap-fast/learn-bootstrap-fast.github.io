The correct option is Create a cross region read replica and plan to promote it during a regional outage.

This approach places a replica in a different region and uses asynchronous replication so your data is continuously copied out of the primary region. If the primary region becomes unavailable you can promote the replica to restore write availability in the surviving region. This provides a strong disaster recovery posture with low recovery time and a typically small recovery point that depends on replication lag, and it avoids the lengthy process of restoring from backups.

Enable high availability with a regional configuration for every instance is incorrect because Cloud SQL High Availability protects against zonal failures inside a single region and it does not protect you if an entire region goes offline.

Increase backup frequency by running gcloud sql backups create more often is incorrect because backups improve recoverability but they do not provide continuity. You would still need to restore to a new instance which increases downtime and may not meet strict recovery objectives during a regional outage.

Enable point in time recovery for all MySQL instances is incorrect because point in time recovery helps recover from corruption or accidental changes and still requires a restore. It does not provide a ready to use instance in another region for rapid failover during a regional outage.
