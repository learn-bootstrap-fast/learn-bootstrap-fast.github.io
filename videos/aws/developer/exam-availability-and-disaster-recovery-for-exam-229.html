The correct options are Add a second Bigtable cluster in another region and enable replication and Schedule recurring exports of tables to a multi region Cloud Storage bucket.

Add a second Bigtable cluster in another region and enable replication ensures the application can keep serving during a full regional outage. Bigtable multi cluster replication keeps data in sync across regions and you can use an application profile with multi cluster routing so traffic automatically fails over to a healthy cluster when one region becomes unavailable.

Schedule recurring exports of tables to a multi region Cloud Storage bucket provides disaster recovery for an extreme event where an entire region and its clusters are lost. Regular exports give you restorable snapshots stored with geographic redundancy so you can import the data into a new Bigtable instance in another region.

Provision a failover cluster in the same region as the primary does not meet the requirement because a regional outage would take down both clusters at the same time.

Operate a single cluster Bigtable instance for reduced complexity cannot provide high availability or disaster recovery when a region fails because there is no secondary serving location.

Turn on Bigtable table backups on the primary instance only does not protect against regional loss since backups are tied to the cluster and region where they are created and could be lost with that region.
