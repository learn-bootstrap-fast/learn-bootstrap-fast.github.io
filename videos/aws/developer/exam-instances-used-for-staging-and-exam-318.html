The correct answer is Configure automated backups on each Cloud SQL instance and set a preferred backup window that falls in off-peak hours.

Cloud SQL provides native daily automated backups with a configurable one hour window per instance. Setting the window to begin around 02:00 UTC ensures the backups run automatically at an off-peak time which reduces impact on testers and keeps costs predictable. This uses the built-in backup service and it supports retention management and recovery.

The option Use Cloud Scheduler to trigger a Cloud Function that calls the Cloud SQL Admin API to start on-demand backups is unnecessary and adds complexity. The service already schedules backups within a window and a custom scheduler does not provide better control of retention or reliability for this requirement.

The option Enable high availability for all instances and rely on replication instead of backups is incorrect. That feature addresses instance or zone outages but it does not protect against data corruption or accidental deletion which is why you still need backups for disaster recovery.

The option Specify a maintenance window on the instances so backups run overnight is incorrect. That setting only governs when maintenance events can occur and it does not control backup scheduling.
