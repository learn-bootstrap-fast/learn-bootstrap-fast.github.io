The correct option is Configure a maintenance exclusion window on the Cloud Spanner instance during peak sales hours.

A maintenance exclusion on a Cloud Spanner instance tells Google Cloud to defer planned maintenance during the specified time range. This is the fastest and most targeted way to keep production safe during peak sales windows because it prevents planned updates from starting when you cannot afford any disruption. You can set exclusions that align with concert on sale events so planned maintenance will be delayed until after the window ends.

Upgrade the Cloud Spanner instance to a multi region configuration to avoid maintenance impact is not correct. A multi region configuration improves availability and durability but it does not stop maintenance from occurring. It also is not an immediate mitigation because it requires planning and additional cost.

Open a Support case to investigate why the instance was down for more than 12 minutes is not correct. While it can be useful for root cause analysis it does not immediately prevent maintenance from interrupting future peak events.

Migrate the workload from Cloud Spanner to a different database to avoid future maintenance is not correct. Migration would be complex and slow and every managed database has maintenance. This does not meet the requirement for immediate action.
