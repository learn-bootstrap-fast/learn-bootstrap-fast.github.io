The correct option is Configure automatic storage growth for the instance because it expands disk capacity automatically as utilization rises and it does this with minimal disruption and no manual intervention.

With automatic storage growth enabled, Cloud SQL monitors available space and increases the allocated storage when usage approaches capacity. The resize occurs online so ingestion continues and service disruption is avoided. This directly addresses a sustained increase in write volume over the next 90 days without requiring operator action.

Enable high availability for the instance improves resilience by providing a standby and automatic failover, yet it does not add storage capacity or grow disks as data increases, so it would not prevent a space outage.

Create a read replica to distribute workloads can offload read traffic, but writes still go to the primary and storage is not automatically expanded, so it does not solve a primary disk capacity problem.

Turn on automated backups for the instance protects data and supports recovery, but it does not manage live storage growth and can even consume additional storage for backup retention.
