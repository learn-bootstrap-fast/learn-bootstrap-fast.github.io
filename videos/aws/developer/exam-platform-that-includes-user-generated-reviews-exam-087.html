The correct option is Firestore in Native mode.

Firestore in Native mode provides a document database that supports flexible and evolving schemas, which lets you add optional fields later without disruptive migrations. It offers real time listeners so new reviews are pushed to clients almost immediately, which matches the requirement for near real time visibility. It scales horizontally to handle high write throughput and is well suited for mobile apps that store text, emojis, and links, with built in indexing and strong client SDK support.

Cloud SQL with JSON columns is a relational database first so while JSON columns provide some flexibility, it is not optimized for massive write rates from a globally distributed mobile app and it does not provide built in real time change listeners to push updates to clients.

Cloud Bigtable is excellent for very high throughput key value and time series workloads, yet it does not offer a document model, secondary indexes, or client side real time listeners. It is not the best fit for ad hoc queries and evolving document style data in a mobile app.

BigQuery with streaming inserts is an analytics data warehouse designed for large scale analytical queries rather than serving low latency application reads and writes. Streaming into BigQuery adds cost and quota considerations and query latencies are not appropriate for interactive real time app features.
