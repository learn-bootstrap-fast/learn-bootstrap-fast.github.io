The correct choice is Firebase with Cloud Functions for Firebase.

Cloud Functions for Firebase can trigger on photo uploads to Firebase Storage and run image processing code that performs grayscale conversion, resizing, and cropping. It scales automatically with no servers to manage and you pay per invocation which keeps costs low for bursty workloads. You can also use Firebase Authentication and data stores to track follower relationships, and then have Cloud Functions for Firebase send push notifications through Firebase Cloud Messaging so followers are notified in near real time when a photo is updated.

Cloud Spanner and Cloud Run is not a good fit because Spanner is a premium globally distributed relational database that is unnecessary for this use case and increases cost. While Cloud Run can handle image processing, this pair does not provide an integrated path for mobile user management and push notifications and it adds complexity that the question asks you to avoid.

Cloud Storage with Pub/Sub and Cloud Run can be assembled to process images and it scales well, but it requires wiring multiple services together and building additional logic for follower management and push notifications. This increases operational work compared to the cohesive Firebase stack that already integrates storage triggers and messaging for mobile apps.

Firebase with Compute Engine managed instance group introduces virtual machine management, autoscaling policies, and patching which raises operational overhead and cost. A serverless approach is preferred for on demand scaling and minimal operations in this scenario.
