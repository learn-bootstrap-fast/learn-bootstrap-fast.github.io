The correct option is Enable global dynamic routing on the VPC.

Dedicated Interconnect terminates in one region and learns on premises routes through Cloud Router. If the VPC uses regional dynamic routing then those learned routes are only available to subnets and resources in the same region as the Cloud Router. A Bare Metal Solution environment connects to your VPC in its own region, so on premises traffic will not reach it when routing is regional. Enabling global dynamic routing on the VPC makes the Cloud Router learned routes available to all regions of that VPC which allows your on premises network to reach the Oracle host IP in the other region using the existing interconnect.

Create an HA VPN tunnel between the two regions is unnecessary and does not meet the requirement. HA VPN connects a VPC to an external network and you do not build VPNs between regions of the same VPC. The issue is the scope of route propagation, not the absence of a tunnel.

Configure VPC Network Peering with a VPC in the other region does not apply because the scenario involves one VPC spanning multiple regions. Peering is used between different VPCs and even then it does not provide transitive reachability for routes learned from on premises through Cloud Router, so it would not solve this path.

Change the VPC dynamic routing mode to regional would make the problem worse because it restricts learned routes to the region of the Cloud Router and would block on premises traffic from reaching resources in other regions.
