The correct option is Firestore.

Firestore is a fully managed document database that stores JSON-like documents with nested fields and arrays, which fits user posts, emoji reactions, and threaded replies that have evolving shapes. It scales horizontally to sustain very high write rates, and the expected 90 million new records per day is well within typical production limits. It provides low latency reads with strong consistency and offers real time listeners and offline support for web and mobile SDKs, which meets the client access needs. It also gives automatic indexing and flexible queries across document fields so teams can iterate on the data model without rigid schema migrations.

Cloud Bigtable excels at massive throughput for key value and wide column workloads such as time series and analytics, but it does not provide native document modeling, secondary indexes, or rich ad hoc queries across nested fields. Building a community app with nested documents and flexible querying would require significant application side work on Cloud Bigtable and it lacks the client SDK features that web and mobile apps often need.

Cloud Spanner is a relational SQL database with strong consistency and global scalability, but it expects a defined schema and is optimized for normalized relational models. Although it can store JSON, evolving document shapes and nested structures map more naturally to a document database, and Cloud Spanner would add unnecessary complexity and cost for this use case.

Cloud Memorystore is a managed Redis or Memcached service that is designed for caching. It is not a system of record and does not offer durable storage, indexed queries, or native document capabilities, so it cannot serve as the primary database for this application.
