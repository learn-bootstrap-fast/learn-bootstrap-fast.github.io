The correct choice is Cloud Spanner. It is a fully managed relational database that delivers strong transactional consistency and scales horizontally to absorb sudden and unpredictable demand while supporting structured records and JSON for semi structured attributes.

This service provides true ACID transactions and a distributed architecture that keeps reads and writes strongly consistent within a region or across regions. It can increase capacity without downtime which lets you meet unpredictable spikes smoothly. It supports JSON columns so you can keep semi structured fields alongside relational tables, and it offers enterprise controls such as encryption with customer managed keys, fine grained IAM, and VPC Service Controls to meet strict regulatory requirements.

Firestore in Native mode is a NoSQL document database that excels at flexible schema and massive scale, but it is not a relational SQL database and it does not support joins or multi row relational constraints. Its transactional model is more limited, so it does not meet the needs of strongly consistent relational workloads.

Cloud SQL with read replicas runs a single primary instance with asynchronous replicas. Replicas can lag and write throughput cannot scale horizontally, so handling sudden spikes in transactional workloads is constrained by the primary and does not meet the requirement for seamless scaling.

AlloyDB for PostgreSQL delivers high performance PostgreSQL with read pools and JSON support, yet it still uses a single primary for writes. This makes it strong for many enterprise scenarios but it does not offer elastic horizontal write scaling for sudden and unpredictable surges at very large scale.
