The correct sequence is Provision a Cloud Spanner instance using a multi regional configuration and then create the database within that instance.

This is correct because Cloud Spanner replication is defined at the instance level. When you choose a multi regional instance configuration, Spanner automatically replicates data across the regions in that configuration and provides low latency reads and high availability through automatic failover. You first create the instance with the desired multi regional configuration and then create the database inside that instance so the database inherits the replication and availability characteristics.

Enable the Data Fusion API and configure pipelines to replicate Cloud Spanner data into other regions after creating a multi regional instance is incorrect because Data Fusion is an ETL service and is not used to implement Spanner replication. Spanner provides built in synchronous replication with multi regional instance configurations, so adding Data Fusion would be unnecessary and would not preserve transactional guarantees.

Create a regional Cloud Spanner instance and use Datastream to push changes to additional regions is incorrect because Datastream performs change data capture and would only provide asynchronous propagation of changes. This would not deliver Spanner’s strong consistency or automatic failover, and you cannot convert a regional instance into a globally replicated setup with external CDC tools.

Create independent Cloud Spanner databases in each region and synchronize writes using Cloud Pub/Sub is incorrect because separate databases coordinated by messaging would be eventually consistent and would not maintain global serializability or ACID transactions. Pub/Sub is not a replication mechanism for Spanner and cannot provide the consistency and failover guarantees required.
