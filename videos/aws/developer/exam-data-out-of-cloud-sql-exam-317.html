The correct option is roles/cloudsql.client and roles/bigtable.user because the job must connect to Cloud SQL without managing instances and it must read and write Bigtable data without administering the Bigtable environment.

This pairing follows least privilege. The Cloud SQL client permission set enables secure connections to instances through the proxy or connectors and does not grant instance administration. The Bigtable user permission set allows reading and mutating table data such as writing shipment event updates and does not allow managing tables or instances.

roles/cloudsql.viewer and roles/bigtable.user is not sufficient because the viewer permission set only allows viewing instance metadata and metrics rather than establishing a connection to the database even though the Bigtable user permission set would allow data writes.

roles/cloudsql.admin and roles/bigtable.reader does not meet requirements because the Bigtable reader permission set is read only so the job cannot write updates and the Cloud SQL admin permission set is broader than needed and violates least privilege.

roles/cloudsql.editor and roles/bigtable.admin grants excessive management privileges in both services which violates least privilege and does not provide any benefit for a pipeline that only needs to connect to Cloud SQL and modify Bigtable data.
