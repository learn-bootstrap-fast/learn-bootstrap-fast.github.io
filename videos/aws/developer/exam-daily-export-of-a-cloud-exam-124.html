The correct answer is Create a Cloud Function that calls the Cloud SQL Admin API export for the PostgreSQL instance to write an SQL dump to Cloud Storage and trigger it daily with Cloud Scheduler.

This approach uses a managed export that produces a plain SQL dump in a Cloud Storage bucket, which directly satisfies the requirement. You can schedule the invocation with Cloud Scheduler and use an HTTP or Pub/Sub trigger, which keeps the design lightweight and serverless. It avoids managing worker infrastructure and reduces operational overhead while using a supported and documented export path for Cloud SQL for PostgreSQL.

Provision a Cloud Composer environment with an Airflow DAG that runs a pg_dump task to create an SQL file in Cloud Storage and configure Cloud Scheduler to trigger the DAG each day is heavier than necessary. Enable automated backups in Cloud SQL and rely on the daily backups instead of performing an export to Cloud Storage does not meet the requirement because automated backups are for recovery and are stored in a managed format.
