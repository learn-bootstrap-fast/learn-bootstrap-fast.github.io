The correct option is Turn on Cloud SQL high availability for the instance so a regional standby is created and automatic failover handles a zonal outage.

Cloud SQL high availability creates a standby in a different zone within the same region and uses synchronous storage replication so failover during a zonal outage is automatic and fast. This configuration meets the 99.95 percent availability target and maintains a single write endpoint because the instance connection name and IP continue to serve the database after failover which minimizes disruption to the application.

Schedule a job with Cloud Scheduler that restores a fresh instance from backup in another zone when the primary becomes unavailable is wrong because restores from backups are manual recovery actions that take significant time and require app reconfiguration which does not meet a high availability target and does not provide minimal disruption.

Create a cross zone read replica and rely on automatic promotion to make it primary when the zone fails is wrong because Cloud SQL read replicas are asynchronous and are not automatically promoted during failures. Promotion is a manual operation and may incur data loss and application downtime which fails the availability requirement.

Use two standalone Cloud SQL instances in different regions and configure the app to write to both at the same time is wrong because dual writes to independent primaries are not supported and cause consistency conflicts. It also violates the requirement to keep one write endpoint and adds complexity without providing automatic failover.
