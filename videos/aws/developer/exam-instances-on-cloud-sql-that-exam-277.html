The correct option is Review and apply rightsizing guidance from the Cloud SQL overprovisioned recommender.

This fleet has run stably for a long period, so the recommender can safely analyze sustained CPU and memory utilization and propose smaller machine types or storage configurations that lower cost while maintaining headroom. The recommender uses long lookback windows and conservative thresholds, so its rightsizing guidance is designed to preserve existing performance levels while reducing waste. It also scales well across multiple instances which makes it an efficient way to lower spend across the fleet.

Enable Cloud SQL Insights and tune queries and indexes to trim storage and CPU use is not the best fit when performance is already acceptable. Insights is a diagnostic tool for query tuning and it can add overhead and effort without guaranteeing material cost savings, and it is unnecessary when the goal is to preserve current performance rather than change workload behavior.

Turn on high availability for each instance to control downtime related expenses increases cost because HA adds a standby instance, more storage, and additional replication traffic. It is valuable for resilience, not for reducing ongoing spend.

Scale up to larger machine types so you can merge databases onto fewer instances typically raises compute costs and consolidation can introduce operational risk and resource contention. There is no reason to scale up or merge when performance is steady and the objective is to cut costs.
