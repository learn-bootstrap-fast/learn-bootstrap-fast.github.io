The correct option is Provision a Memorystore for Redis instance in each region and have the application connect to the nearest regional endpoint.

Memorystore for Redis is a regional service and its instances use private regional IP addresses. Replication and failover in the standard tier are only within a region. There is no cross region replication or automatic multi region failover, so the right way to achieve low latency and resilience across multiple regions is to run a separate cache in each region and have clients connect to the local endpoint. Applications often pair this with a multi region authoritative datastore and treat the cache as ephemeral.

Configure a single Memorystore for Redis instance and turn on cross region replication is incorrect because the product does not support cross region replication. Replication is only across zones within the same region in the standard tier.

Choose a multi regional Memorystore for Redis deployment to fail over automatically across regions is incorrect because there is no multi regional deployment tier for Memorystore for Redis.

Place a global load balancer in front of Redis to route traffic between regions is incorrect because Memorystore exposes regional private endpoints inside a VPC and cannot sit behind a global load balancer. This approach would also not solve data consistency or failover needs across regions.
