The correct option is Database Migration Service.

This service supports an initial load of data from a self managed MySQL source into Cloud SQL and then keeps the destination in sync using continuous change replication. That lets you point tests at the Cloud SQL target while the source remains live and it allows you to choose a planned cutover time. Because only the final cutover requires a brief outage, total downtime is typically minutes and fits the less than ten minutes requirement.

Datastream is designed for change data capture into analytics and integration targets such as BigQuery, Cloud Storage, or Pub or Sub. It does not orchestrate end to end migrations into Cloud SQL and it does not manage database cutover.

Cloud SQL import and export relies on dump and restore which usually requires extended downtime for large datasets and it cannot keep the target synchronized for pre cutover testing.

Migrate to Virtual Machines moves virtual machines to Compute Engine rather than migrating database data into Cloud SQL, so it does not meet the requirement for a managed database migration with minimal downtime.
