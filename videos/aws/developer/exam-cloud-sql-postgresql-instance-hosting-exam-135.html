The correct answers are Configure a maintenance window during off peak hours and Enable high availability for the Cloud SQL instance.

A maintenance window lets you choose when Google applies scheduled updates so they occur during your lowest traffic periods. This reduces user facing errors because changes happen when fewer sessions are active and it also gives you predictability to prepare your application. Aligning the maintenance window with off peak usage directly minimizes the impact users experience.

Enabling high availability creates a standby instance in another zone with synchronous replication. During maintenance Google can update the standby first and then perform a controlled failover which shortens the interruption to a brief reconnection event. High availability therefore reduces downtime and lessens user impact while you continue to use Cloud SQL.

Use Cloud Spanner instead of Cloud SQL does not meet the requirement to continue using Cloud SQL and it introduces a migration to a different service that is unnecessary for solving brief maintenance interruptions.

Implement client side retries with exponential backoff can help mask transient errors but it does not reduce the actual maintenance downtime and transactions can still fail during a failover event.

Enable Cloud SQL Insights helps analyze query performance and troubleshoot latency but it does not change maintenance behavior or availability and it will not reduce downtime.
