The correct option is Introduce Cloud Memorystore for Redis as a cache for hot user profiles. This adds a fast in-memory layer that serves repeated profile lookups with very low latency and it reduces the number of reads hitting Firestore which lowers read costs while maintaining performance for roughly 30 thousand predictions per minute.

A cache-aside approach works well here. The service checks the cache first and serves hits immediately. On a miss it reads from Firestore and places the document into the cache for subsequent requests. You can use time to live settings and simple invalidation on updates so the cache stays fresh while Firestore remains the source of truth. Because Firestore bills per document read, every cache hit avoids a billable read, so the savings grow with traffic while the cache maintains submillisecond access for hot keys.

Migrate the user profile store to Cloud SQL for stronger transactional guarantees is not a good fit. The workload is read heavy with simple document retrievals and does not require complex relational transactions. Moving to a relational database adds migration effort and ongoing instance costs and connection scaling concerns and it is unlikely to match the low latency and horizontal read throughput that an in-memory cache provides for this pattern.

Move the user profiles to Cloud Storage to reduce storage expenses is inappropriate for profile serving. Object storage is not optimized for high QPS document lookups with very low latency or frequent small updates. It may lower storage costs but it would likely increase request latency and operational complexity and it does not meet the real-time access requirement.

Refine Firestore query patterns and add composite indexes to speed lookups can improve certain filtered queries but it does not reduce read charges because each document read is still billed. Profile retrieval is often by document ID which is already efficient, and additional indexes can even increase write costs. This does not meet the goal of lowering read costs while maintaining performance.
