The correct option is Turn on automatic storage increase for the instance.

Automatic storage increase allows Cloud SQL to expand disk capacity when free space becomes low. This occurs without operator intervention which keeps the environment dependable during rapid growth. It scales incrementally up to the maximum supported storage for the database engine so a target around 58 TB can be accommodated when the chosen engine and instance settings support that size.

Use local SSD for the database storage is not supported by Cloud SQL and local SSD is ephemeral which is not suitable for durable managed database storage. It would not provide automatic capacity growth and would reduce dependability.

Enable high availability configuration for the instance improves resilience and failover but it does not increase storage capacity and it does not automate storage growth.

Create a Cloud Scheduler job that calls the Cloud SQL Admin API to grow disk size on alerts adds unnecessary operational complexity and risk. The built in automatic storage increase already performs this function more reliably and with less manual effort.
