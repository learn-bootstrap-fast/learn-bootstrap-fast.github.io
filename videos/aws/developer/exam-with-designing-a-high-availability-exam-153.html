The correct choice is Configure a Bigtable instance with clusters in three regions with multi cluster routing and replication turned on. This design provides automatic failover across regions and keeps write replication delays very low which supports an RPO under 4 minutes and an RTO under 9 minutes. It also allows traffic to be served from clusters close to users in North America and Europe which keeps latency low while tolerating the loss of a region.

This approach uses multi cluster replication to replicate data between clusters in different regions and it uses multi cluster routing so clients are automatically directed to the nearest healthy cluster. Replication typically occurs within seconds which supports a sub four minute RPO. Because no restore is required and traffic can be routed to a surviving cluster, failover is quick which keeps RTO well below nine minutes. Placing clusters in North America and Europe satisfies the latency requirement while the third region adds resilience to regional outages.

Create a single regional Bigtable cluster and stream writes to another region using Dataflow jobs is not appropriate because replication would be application managed with additional lag and operational complexity. There is no native automatic failover and recovery would likely exceed the RTO target while the RPO would depend on pipeline delay which is not guaranteed to be under four minutes.

Provision a single Bigtable cluster in one region and schedule snapshots every 20 minutes cannot meet the RPO requirement because a 20 minute snapshot interval yields a 20 minute potential data loss window. Restoring from snapshots also takes time, which makes it unlikely to meet the nine minute RTO and it does not maintain low latency for users in multiple continents during an outage.

Run a lone Bigtable cluster in one region and rely on cross regional backups is a disaster recovery pattern rather than a high availability one. Backups do not provide continuous replication or automatic failover, so both RPO and RTO would exceed the targets. This setup also cannot deliver low latency to both North America and Europe during a regional failure.
