The correct choice is Document NoSQL Database because it natively stores JSON events, scales horizontally across nodes, and lets the data model evolve without enforcing rigid schemas.

This database type persists data as self-contained documents that map naturally to JSON, which makes ingest and query of semi-structured events straightforward. It supports schema flexibility so new fields can appear in events without disruptive migrations, which aligns with fast-changing analytics payloads. It also provides horizontal scalability through partitioning and sharding so it can sustain very high write throughput and grow across nodes as daily volumes reach tens of terabytes.

Key-value NoSQL Database is not a good fit because it focuses on simple key lookups and opaque values. This type typically lacks rich querying, indexing across document fields, and nested structure awareness that are needed for analytics on complex JSON events.

Time-series NoSQL Database is optimized for timestamped measurements and time-window queries, retention policies, and rollups. While events have timestamps, the workload described requires flexible JSON modeling and broader query patterns than a time-series engine is designed to provide.

Relational SQL Database expects a predefined schema and typically requires schema migrations as fields change. It can scale, yet doing so at the write rates and fluid schemas described often demands complex sharding strategies, which makes it a less appropriate default for large-scale semi-structured event ingestion.
