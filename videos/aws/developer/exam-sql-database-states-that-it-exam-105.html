The correct option is Set up private services access in the VPC and create the instance with a private IP address.

This approach creates a private connection between your VPC and the Google managed service network so the Cloud SQL instance gets a private address and no public IP. Your workloads in the selected VPC can reach the database over private RFC 1918 space through the service networking peering which meets the requirement to restrict access to VPC networks within Google Cloud.

Create a firewall rule that opens the database port to your application subnet is incorrect because Cloud SQL is a managed service that does not live in your VPC and your VPC firewall rules do not make a publicly addressed instance private. If the instance had only a public IP this rule would not satisfy the requirement to avoid any public IP.

Enable Serverless VPC Access on the project to allow private connectivity is incorrect because this only lets serverless products send traffic into your VPC. It does not assign a private address to Cloud SQL and it does not create the required private connectivity to the managed service.

Add an authorized networks entry that uses your internal subnet range is incorrect because authorized networks apply only to public IP connectivity. Using this feature would require a public IP on the instance which violates the requirement.
