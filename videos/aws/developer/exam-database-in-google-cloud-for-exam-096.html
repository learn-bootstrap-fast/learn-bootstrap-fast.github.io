The correct option is Build a MongoDB cluster on Compute Engine across multiple regions and serve reads from the nearest regional replica while directing all writes to the primary. This approach satisfies the need for high availability and low read latency across continents while maintaining a single authoritative writer.

MongoDB replica sets are designed for a primary that handles all writes and secondaries that can serve reads. Placing secondaries in regions close to users lets you use a nearest read preference to reduce latency for North America and Europe. Keeping a single primary preserves write ordering and consistency while automatic elections provide high availability if the primary fails. Compute Engine gives you flexible placement across regions and zones with control over machine types and storage so you can meet the write throughput requirement.

Run a MongoDB replica set on Compute Engine instances in one region and direct both reads and writes to the primary instance is incorrect because a single region cannot provide low latency reads for users in multiple continents and it concentrates failure risk in one location which weakens availability.
