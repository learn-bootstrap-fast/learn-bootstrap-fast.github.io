The correct option is Define a weekend maintenance window when the team is offline, set lower environments to update first, and schedule production to update later.

Cloud SQL allows you to set a preferred maintenance window by day and hour so you can choose a time when users are not active. Since the helpdesk operates Monday to Friday during business hours, running maintenance on the weekend prevents disruption. Rolling changes through development and staging first gives you a safe place to validate updates and then scheduling production afterward minimizes the chance of impacting the support team.

Turn on maintenance notifications for the team and postpone updates until after notices are sent is not sufficient because notifications do not control when maintenance occurs. You still need to define a maintenance window and plan the rollout order across environments to avoid user impact.

Configure the Cloud SQL instance with high availability enabled does not guarantee a maintenance experience without interruption. HA can reduce disruption by failing over to a standby but there is still a brief failover event and it does not let you choose a user friendly time for the work.

Create a cross region failover replica to handle maintenance updates is not appropriate because cross region replicas in Cloud SQL are read only and are not automatic failover targets. Promoting a replica is manual and introduces downtime and it adds unnecessary complexity for routine maintenance.
