The correct option is Turn on the automatic storage increase setting for the Cloud SQL instance.

The automatic storage increase feature lets Cloud SQL grow disk capacity when free space gets low and it does so without manual intervention. This prevents storage exhaustion which protects performance and availability as the database scales. Enabling automatic storage increase meets the requirement to expand capacity automatically over the next months while keeping performance steady.

Set up a Cloud Scheduler job that checks disk usage and calls the Cloud SQL Admin API to increase storage is custom automation that is reactive and brittle. It can lag behind rapid growth and it adds operational overhead. If storage fills before the job runs then performance and availability can suffer, which does not meet the requirement.

Cloud Spanner is a different managed database that would require a migration and a change in technology. The scenario is already on Cloud SQL for PostgreSQL and only needs automatic growth of storage, so moving to another product is unnecessary and risky.

Configure a Cloud Monitoring alert when disk utilization reaches 85 percent only sends a notification and still requires a person or another tool to act. This does not provide automatic capacity growth and can allow performance issues if action is delayed.
