The correct configuration is Pub/Sub with global endpoints and message storage in a continental multi-region.

This choice keeps client to service latency low because Pub/Sub uses a global service entry point that routes clients to the nearest edge and it also provides high availability and disaster recovery because messages are stored in a continental multi region with replication across independent regions. This satisfies the requirement to stay within a single continent while protecting against regional failures and still handling tens of millions of events per hour.

Pub/Sub with regional endpoints in a single region concentrates the control plane and data plane in one region which does not meet the disaster recovery requirement. A regional outage would disrupt ingestion and delivery and clients spread across the continent can also see higher tail latency if forced to reach that single region.

Pub/Sub with global endpoints and message storage in a single region improves client ingress latency but still fails the disaster recovery goal because the data is stored in only one region. A regional failure would interrupt processing and availability.

Pub/Sub Lite with zonal topics in two zones of one region is designed for cost sensitive and predictable throughput workloads. Zonal topics do not provide cross region replication and even with two zones the design cannot survive a regional outage and it adds operational overhead that is unnecessary for this requirement.
