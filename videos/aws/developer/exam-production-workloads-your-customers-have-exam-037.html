The correct answers are: Enable high availability for the Cloud SQL instance with automatic failover and Configure a preferred maintenance window during off peak hours.

With high availability Cloud SQL runs a primary and a standby in different zones with synchronous replication and automatic failover. During maintenance Google can update the standby first and then perform a controlled failover so connections experience only a brief switchover. This greatly reduces visible downtime while remaining simple to operate because Cloud SQL manages the replication and failover.

A preferred maintenance window lets you choose when maintenance is performed so it occurs during off peak hours. When combined with high availability it minimizes both the duration and the user impact of maintenance events while keeping administration straightforward.

Subscribe to Cloud SQL maintenance notifications only informs you about upcoming work and does not change maintenance behavior or prevent dropped connections. This is useful for planning but it does not reduce impact by itself.

Create a read replica and route read only queries to it during maintenance does not protect write traffic and replicas are not an automatic failover target for maintenance in Cloud SQL. This adds complexity and still leaves the primary write workload exposed.

Add exponential backoff and retry logic to the application database client can help clients recover from transient errors but it does not avoid the brief outage during maintenance. It is complementary to high availability and a preferred maintenance window rather than a replacement.
