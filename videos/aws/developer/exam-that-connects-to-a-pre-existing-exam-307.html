The correct choice is Create a new service account and grant it the Firestore Data Viewer role.

This follows the principle of least privilege because a dedicated service account isolates the backend from other workloads and a read only permission set grants only what is needed to run queries and read documents. It lets the service compute summary metrics from Firestore while preventing any writes updates or deletes and it avoids project wide permissions.

Create a new service account and grant it the Firestore Editor role is overly permissive for a read only workload. This role includes write and delete capabilities on entities and indexes which are unnecessary and increase risk.

Reuse the existing service account that writes data into the same database violates separation of duties and least privilege because it carries write permissions that the reporting service does not need. Using separate identities simplifies auditing and key rotation and limits blast radius.

Grant the Project Viewer role to the Compute Engine default service account is both too broad and also does not provide Firestore document access because Firestore data requires the product specific data roles. Relying on the default service account is discouraged in production and it does not meet the goal of granting only the minimum access.
