This approach uses lightweight agents inside the data center to read from NFS or SMB shares and supports scheduling daily runs with incremental syncing, retries, and parallelization. Delivering the data into Cloud Storage matches the expected ingestion path for BigQuery so you can load from buckets on a schedule.

Build a transfer service on Compute Engine that runs a copy job from Cloud Scheduler requires you to design, secure, monitor, and scale your own transfer tooling. Use gsutil to manually copy the data from the data center to Cloud Storage each day relies on human intervention and ad hoc processes, which is error prone and not dependable at the 3 TB per day scale. It also adds unnecessary operational burden.

BigQuery Data Transfer Service is designed for moving data from supported SaaS sources or from Cloud Storage into BigQuery. It does not ingest files directly from on premises file shares into Cloud Storage, so it does not meet the source and path required here.
