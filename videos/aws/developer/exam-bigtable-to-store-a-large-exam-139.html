The correct choice is Create a multi-cluster Bigtable instance with clusters placed in separate regions within a single continent.

This configuration replicates data between clusters and the client library can route traffic to the nearest healthy cluster which keeps read and write latency low in steady state and during failover. Placing clusters in different regions within one continent provides regional fault tolerance and disaster recovery while keeping inter region latency small enough for fast replication and quick client routing. It also allows horizontal scaling by adding nodes per cluster to sustain very high concurrency while maintaining low latency.

Configure a multi-cluster instance with clusters distributed across different zones in the same region only protects against zonal failures. It does not provide protection from a regional outage, so it does not meet the disaster recovery requirement.

Use a zonal instance with asynchronous replication configured within the same zone is not a valid Bigtable setup because replication requires distinct clusters in different zones. A single zone deployment offers no failover or disaster recovery.

Provision a single cluster instance and scale out the node count within one zone can improve throughput and lower latency, but it remains a single point of failure and does not provide cross zone or cross region disaster recovery.
