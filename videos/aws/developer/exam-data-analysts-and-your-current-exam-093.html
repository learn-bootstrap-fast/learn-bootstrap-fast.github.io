The correct option is Provision Cloud SQL read replicas and give analysts read only access to those replicas.

This approach provides separate read only instances that mirror the primary, which lets the analysts run their queries without competing with application writes. It keeps the primary responsive for application traffic because analytical queries are isolated to the readers while the primary focuses on transactions. It is simple to enable within Cloud SQL and you can scale by adding more readers if the team or workload grows. Any small replication lag is usually acceptable for ad hoc analysis while still providing full access to the data set.

Create SQL views for each analyst and grant access to those views on the primary instance is incorrect because the queries still run on the primary, so analytics would contend with production traffic and the administrative burden grows without improving isolation.

Use Datastream to replicate from Cloud SQL into BigQuery and instruct analysts to query BigQuery can work for warehouse style analytics, yet it is not the simplest path for this requirement. It adds additional services and pipelines, increases cost and governance complexity, and may not preserve the transactional behavior analysts expect from the source.

Place Memorystore in front of the database and require analysts to query only cached data is not viable because this is a caching service for key value access and it does not support ad hoc SQL across the complete relational dataset. It also would not guarantee that analysts see comprehensive or current results.
