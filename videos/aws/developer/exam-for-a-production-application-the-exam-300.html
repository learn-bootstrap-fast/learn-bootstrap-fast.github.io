The correct configuration is Enable private services access for your VPC and create the instance with a private IP.

This approach provisions the database with an internal address through Service Networking so the instance has no public endpoint. Connections can originate only from resources in your VPC or from connected networks such as Shared VPC, VPC peering, Cloud VPN, or Cloud Interconnect. This satisfies the requirement that the database be reachable only from workloads inside Google Cloud and not from the public internet.

Configure a VPC Service Controls perimeter around the project is not sufficient because it protects access to supported Google APIs and reduces data exfiltration risk, yet it does not govern database connection paths to Cloud SQL and does not create a private endpoint.

Configure a Cloud NAT gateway for the instance is unrelated to restricting inbound connectivity. It provides outbound internet access for private resources and does not make a managed database privately reachable only within your networks.

Enable a public IP on the instance and restrict sources with authorized networks still exposes a public endpoint on the internet. Even with source restrictions in place, the stated policy requires no public exposure, so this does not meet the requirement.
