The correct option is Enable automatic storage increases on the Cloud SQL instance.

Automatic storage increases in Cloud SQL for PostgreSQL will grow the disk as free space becomes low which avoids manual interventions and downtime. You can set an upper limit that comfortably exceeds the projected 45 TB and the platform will expand storage gradually as needed. This directly meets the requirement for automatic capacity growth with minimal ongoing operational effort.

Migrate the workload to Cloud Spanner is not appropriate because it introduces a complex migration to a different database product and SQL dialect. The need is simple storage growth for an existing PostgreSQL workload and Cloud SQL already provides this natively.

Create a Cloud Monitoring alert when disk usage passes 85 percent only notifies you and does not expand storage. It would still require manual action which conflicts with the goal of minimal operational effort.

Resize the instance to a larger machine type changes CPU and memory resources but does not increase disk capacity. Storage growth would still need to be handled separately and manually which does not satisfy the requirement.
