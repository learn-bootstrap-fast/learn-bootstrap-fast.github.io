The correct option is Create a Cloud SQL for MySQL instance configured as a regional high availability deployment that uses synchronous replication and automatic failover.

Cloud SQL regional high availability for MySQL places a primary and standby in separate zones within the same region and uses synchronous replication so committed transactions are on both nodes. This gives an RPO of zero. The service provides automatic failover which minimizes downtime and the managed nature of the service keeps operational work low. Google offers a 99.95 percent monthly uptime SLA for Cloud SQL high availability which matches the requirement.

Use Cloud Firestore in Datastore mode with a multi-region configuration is not appropriate because it is a NoSQL document database and not a MySQL compatible relational engine. It would require significant application changes and does not meet the requirement to migrate a MySQL backend.

Use Cloud Bigtable configured as a multi-cluster instance in one region is not suitable because Bigtable is a wide column NoSQL database and does not support MySQL or SQL semantics. Its replication is eventually consistent which does not guarantee an RPO of zero.
