The correct option is SELECT trip_id FROM shipments WHERE courier_id=@courierId AND ship_date=@shipDate.

This query uses named parameters which Cloud Spanner supports and it applies equality predicates to both the courier and the date so it precisely answers the need to find trips for a given courier on a particular calendar day. Equality filters with an AND condition are highly selective and they can efficiently use an appropriate secondary index on courier_id and ship_date which maximizes performance while also allowing plan reuse and safe parameter binding.

SELECT trip_id FROM shipments WHERE courier_id LIKE @courierId AND ship_date=@shipDate is not ideal because LIKE is intended for pattern matching and not exact matching of identifiers. It can lead to unintended matches if wildcards are used and even without wildcards it offers no benefit over equality while potentially reducing the effectiveness of index lookups.
