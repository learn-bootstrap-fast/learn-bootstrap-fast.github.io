The correct options are Distribute read traffic to read replicas in different zones and Configure a failover replica in a separate zone within the same region.

Distribute read traffic to read replicas in different zones ensures that read workloads continue even if a single zone fails. Read replicas placed in other zones remain available so your application can still serve queries that do not require writes while the primary is impacted. This improves availability and reduces pressure on the primary under normal conditions.

Configure a failover replica in a separate zone within the same region provides automatic failover for the primary instance. If the zone hosting the primary becomes unavailable, Cloud SQL promotes the standby in the other zone to primary which preserves write availability and keeps the service operating during a zonal outage.

Create a manual snapshot every hour does not provide availability during an outage. Snapshots are for point in time recovery and require a restore to a new instance which involves downtime.

Enable automated backups also focuses on recovery rather than continuity. Backups protect data but they do not keep the database serving traffic during a zonal failure.

Cloud Spanner offers high availability across zones and regions but it is a different database service and migrating is not implied by the requirement to keep a Cloud SQL for PostgreSQL instance available within the region.
