The correct answers are Enable high availability for the instance and Use read replicas.

Enable high availability for the instance gives the Cloud SQL instance a primary and standby in different zones with automatic failover, which significantly shortens disruption during an unexpected outage. This configuration also qualifies the instance for the Cloud SQL SLA of 99.95 percent monthly uptime, which meets the team’s target while staying on Cloud SQL.

Use read replicas helps reduce customer impact during a failover by offloading read traffic so fewer requests depend on the primary. Replicas can continue serving reads and can be promoted if needed, which can shorten recovery time in a prolonged incident. This complements high availability rather than replacing it and together they improve resilience and reduce perceived downtime.

Set a maintenance window for controlled failover testing only schedules when maintenance can occur and does not change behavior during unexpected failovers, so it does not improve availability during unplanned events.

Enable automatic backups protects data for recovery but does not affect failover speed or availability, so it will not reduce downtime during transient outages.

Cloud Spanner is a different database service and would not satisfy the requirement to stay on Cloud SQL. Although it offers strong availability, it does not align with the stated constraint.
