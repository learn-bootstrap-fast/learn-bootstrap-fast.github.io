The correct option is Choose Firestore using Native mode.

This choice fits a schema that changes as the curriculum evolves because documents can hold varying fields per lesson and you can evolve them without schema migrations. It also provides real time listeners in the client SDKs so followers can see updates almost immediately when a learner finishes an activity. It is fully managed and is designed for mobile and web applications that need low latency synchronization and offline support. Media such as emojis animated gifs and short voice clips can be stored in a bucket while the database stores metadata and references to those assets which keeps the feed responsive.

Cloud Spanner with interleaved tables using learners as parent rows is a relational service that expects a defined schema and it is optimized for strong consistency and global scale rather than frequent flexible attribute changes. It does not provide built in real time client subscriptions so you would need to build additional infrastructure to push updates to followers which adds complexity that is unnecessary here.

Cloud SQL for PostgreSQL with LISTEN and NOTIFY can signal server side sessions but it is not a client facing real time sync solution and it does not offer the mobile or web SDK features that automatically propagate changes to end users. It also relies on a rigid relational schema and LISTEN and NOTIFY are not designed for high fan out notification patterns to many followers across devices.

Firestore in Datastore mode is optimized for server centric workloads and does not offer the real time client listeners and offline capabilities that are central to this use case. It is less suitable when you need immediate updates in user interfaces for mobile or web clients.
