The correct choice is Cloud Spanner using a multi-region instance and interleaved tables.

This service provides externally consistent transactions and strongly consistent reads and writes across continents using multi-region instance configurations. It scales horizontally to handle tens of millions of users while preserving strict consistency. Interleaved tables colocate related rows which helps keep parent and child data together and improves access patterns such as per region counters and global rollups for live charts.

Cloud Bigtable with multi-cluster replication can deliver very low latency and high throughput, yet its replication across clusters is eventually consistent which means recent writes may not be visible immediately in other regions. This fails the requirement for strong global consistency and it does not offer SQL or multi row transactions that make counters and aggregations simpler.

Cloud SQL with sharding and read replicas is regional and cross region replicas are asynchronous which breaks strong consistency and introduces replication lag. Manual sharding adds operational overhead and still does not provide elastic multi region write scalability at a global level.

BigQuery with streaming inserts enabled is an analytical data warehouse designed for large scale analytics rather than high QPS transactional serving. Streaming inserts go into a buffer and query visibility can be delayed, so updates are not instantly and strongly consistent for live leaderboards.
