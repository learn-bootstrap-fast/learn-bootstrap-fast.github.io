The correct actions are Introduce Cloud Memorystore for Redis to cache frequently requested data and session lookups and Design schema and queries with appropriate indexing table partitioning and sharding where it aligns with access patterns.

Memorystore for Redis offloads hot reads and session lookups from the primary database which reduces latency and decreases database CPU and IOPS. Because it is a managed in memory cache you gain performance without taking on operational overhead and you typically lower total cost by serving repeated requests from the cache rather than from the database.

Designing schema and queries with appropriate indexing table partitioning and sharding aligned to access patterns improves query efficiency and helps the database scale predictably. Proper indexes avoid full scans and good partitioning and sharding reduce contention and hot spots which improves throughput. These practices let you meet performance goals on smaller instances and with fewer replicas which keeps costs reasonable.

Use Cloud Spanner with a multi-region configuration for every workload regardless of traffic patterns is not cost efficient because multi region configurations are premium and should be reserved for workloads that truly need global availability and very high write scalability. Choosing Spanner and its topology should be driven by consistency and scale requirements rather than using it by default.

Configure Cloud SQL with automated backups and binary logging turned off to reduce overhead is risky because automated backups and binary logging enable recovery and point in time restore and also support replication. Disabling them might save a small amount of overhead but it greatly increases operational and data loss risk which is not acceptable.

Enable automatic instance autoscaling for Cloud SQL to handle sudden spikes in demand is not a valid approach because Cloud SQL does not provide automatic CPU and memory autoscaling for instances. Cloud SQL supports automatic storage increase and you handle bursts with techniques like right sizing instances read replicas and connection pooling.
