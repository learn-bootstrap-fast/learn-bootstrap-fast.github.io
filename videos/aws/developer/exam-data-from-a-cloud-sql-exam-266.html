The correct option is Configure Cloud SQL native replication and use CMEK.

Cloud SQL for MySQL supports cross region read replicas that you can place in europe-west4 while the primary remains in us-central1. This native replication keeps data integrity through managed MySQL replication and the service encrypts data in transit. Using customer managed encryption keys ensures that data at rest and backups are encrypted with your own keys in both regions. You create the replica in europe-west4 and supply a key in that region so the standby remains encrypted under your control. This approach gives you a straightforward path to disaster recovery because you can promote the replica if the primary region is unavailable.

Use Pub/Sub with Cloud Functions to write changes to a second database is not a supported or reliable mechanism for MySQL replication. It does not provide ordered transactional consistency and it cannot act as a managed standby for Cloud SQL, which risks data loss and integrity issues.

Enable CMEK on the primary Cloud SQL for MySQL instance does not meet the disaster recovery requirement because it does not create a standby in europe-west4. In addition, CMEK must be configured when an instance is created, so you cannot simply turn it on later for an existing primary, and enabling it on the primary alone would not set up replication.

Datastream is a change data capture service that is commonly used for migrations or analytics pipelines. It does not create a managed MySQL standby in Cloud SQL and it does not provide the simple promotion and failover workflow you need for disaster recovery.
