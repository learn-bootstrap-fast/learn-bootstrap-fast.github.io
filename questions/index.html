To comply with the security requirement of encrypting all data at rest in DynamoDB, you can leverage built-in server-side encryption mechanisms provided by AWS. The two correct options are:

Utilize encryption managed by AWS (such as an Amazon-owned encryption key)<\/b> and Implement encryption using an AWS Key Management Service (KMS) managed key<\/b>. These choices enable DynamoDB to perform server-side encryption automatically, protecting your data as it's stored and removing the burden of data key management from your development team.

The option Apply encryption with your own (client-side) keys before storing the data<\/i> refers to client-side encryption, which is NOT required when DynamoDB's server-side encryption is enabled. While client-side encryption is possible, it is not necessary to simply meet the requirement of encryption at rest and adds additional complexity.

The other alternative, Modify your application to call the AWS SDK for decryption on read operations<\/i>, confuses data access with data protection. DynamoDB handles encryption and decryption transparently with server-side encryption, so there is no need for your application to explicitly decrypt data retrieved from the database.

Tip:<\/b> For most use cases, simply enabling server-side encryption in DynamoDB\u2014either with the default AWS owned key or an AWS managed (KMS) key\u2014will fully satisfy mandates for encrypting data at rest with minimal overhead or code changes.<\/p>", "query": "
